## 4. HARA 设计（`01-hara-v0.1.md`）

### 4.1 危险源识别方法

**IEC 61508-1 §7.3 + IMO MASS Code 功能分类驱动**：

以 5 大功能类作为危险源识别的顶层结构，与 NLM 检索到的 MASS HAZID/STPA 文献模式一致（来源 🟢 safety_verification 笔记本）：

| 类别代码 | 类别名称 | 来源映射 |
|---|---|---|
| **CAT-A** | 碰撞与搁浅 | IMO MASS Code Part 2 Chapter 1 + COLREGs Rule 8/16/17 |
| **CAT-B** | 自主决策不安全控制行为（UCA）| STAMP/STPA 文献；M4/M5/M6 核心 |
| **CAT-C** | 感知降质与 SOTIF 触发 | ISO 21448 功能不足；M2 + M7 §11.3 |
| **CAT-D** | 连接性丧失与网络安全 | IMO MASS Code + IACS UR E26/E27；D4 场景 |
| **CAT-E** | HMI / 人机交互失效 | IMO MASS Code Human Oversight；M8 透明性 |

每类在 M1–M7 关键模块上展开 ≈ 4–7 条危险源，总目标 ≥ 30 条。M8 只在 CAT-E 出现（M8 是 HMI 层）。

### 4.2 HARA 表格 Schema

每行字段（顺序即列顺序）：

| 列号 | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | **Hazard-ID** | `H-{nn}` | 顺序编号，H-01 起 |
| 2 | **Category** | CAT-A/B/C/D/E | 上节 5 类 |
| 3 | **Module** | M1–M8 | 主责模块 |
| 4 | **Failure Description** | Text | 失效事件（什么失效） |
| 5 | **Consequence** | Text | 对船舶安全的后果（最坏路径）|
| 6 | **Severity** | C1–C4 | IEC 61508-1 Annex D（见 §4.3）|
| 7 | **Exposure** | F1–F3 | IEC 61508-1 Annex D（见 §4.3）|
| 8 | **SIL (Risk Graph)** | 0/1/2/3 | 风险图输出（见 §4.4）|
| 9 | **SIF Reference** | SIF-{nn} | 映射到 §4.6 SIF 列表 |
| 10 | **ODD-Subdomain** | ODD-A/B/C/D / ALL | 触发子域（见 §4.5）|
| 11 | **Health-State** | NOM/DEG/CRIT / ANY | 健康态约束（见 §4.5）|
| 12 | **Mitigation (Design)** | Text | 当前架构/代码层缓解措施 |
| 13 | **Residual Risk** | Low / Medium / High | 缓解后残余等级（见 §4.7）|
| 14 | **Notes** | Text | [HAZID 校准] 标注 + finding ID |

> **版本控制**：v0.1 表头须写明"初始版本，参数待 HAZID RUN-001 (8/19) 校准"。

### 4.3 IEC 61508-1 Annex D 海事适配尺度

**严重度（Severity）海事适配：**

| 等级 | 标准定义 | 海事适配（MASS FCB 场景）|
|---|---|---|
| **C1** | 轻微不适，无伤亡 | 轻微偏航 / 速度暂时异常，无 CPA 威胁 |
| **C2** | 严重伤害，可逆 | 与目标船险近 CPA < 0.3 nm，需紧急操作；财产轻损 |
| **C3** | 极严重伤害，不可逆；1 人 | 碰撞发生 / 人员落水 / 严重搁浅（修复成本高）|
| **C4** | 灾难性，多人伤亡 | 沉船 / 多人伤亡 / 大面积环境污染 |

**暴露频率（Exposure）海事适配：**

| 等级 | 标准定义 | 海事适配 |
|---|---|---|
| **F1** | 年或更少 | 极端气象（Beaufort ≥ 7）+ 稠密交通同时出现 |
| **F2** | 月到年 | 港口进出 / 能见度 < 0.5 nm / TSS 区域 |
| **F3** | 周到月 | 正常开阔水域航行期间日常操纵 |

### 4.5 ODD 4 子域 × 3 健康态覆盖策略

**DoD 要求**：ODD 4 子域 × 3 健康态全覆盖（ADR-002/003 对齐）。

实现方式：**在 HARA 表每行加 ODD-Subdomain + Health-State 两列**（列 10、11），而非以 ODD 为主轴重组表格。原因：CCS 审查员熟悉以功能类为主轴的 IEC 61508 HARA 格式；ODD 覆盖通过列筛选可验证。

**ODD 子域定义**（ADR-003 §3.3 工程实现层）：

| 子域 | 描述 | 典型危险敏感度 |
|---|---|---|
| **ODD-A** | 开阔水域，正常气象，低交通密度 | CAT-C（感知降质概率低）|
| **ODD-B** | 港口近岸，受限水道，高交通密度 | CAT-A（碰撞/搁浅高）+ CAT-E（ROC 监督高）|
| **ODD-C** | 能见度受限（雾/夜）或强风浪 | CAT-C（感知降质）+ CAT-B（UCA 触发）|
| **ODD-D** | ODD 越界 / 待 ROC 接管状态 | CAT-D（连接性）+ CAT-E（ToR 压力）|

**健康态定义**（架构 §3 + M1 ODD Manager）：

| 健康态 | 描述 | M7 响应 |
|---|---|---|
| **NOMINAL** | 所有模块在 KPI 内运行 | 正常监控 |
| **DEGRADED** | ≥1 模块降级但系统可继续运行 | 升级 SOTIF 告警；ToR 缩短 |
| **CRITICAL** | 安全约束受损；需 MRC 或 D2 降级 | 触发 MRM；请求 ROC 介入 |

**覆盖验证**：危险源表完成后，对 `ODD-Subdomain × Health-State` 组合（4×3=12 格）做交叉统计，确保每格至少 1 条危险源。允许 `ALL` 标注（跨子域/跨健康态危险源）。

### 4.7 残余风险分级

每条危险源评估缓解措施后的残余风险等级：

| 等级 | 标准 | 含义 |
|---|---|---|
| **Low** | 缓解措施完全实现；风险图 SIL 分配已满足 | 可接受，无需额外动作 |
| **Medium** | 缓解措施部分实现或依赖 HAZID 校准参数 | 可接受，HAZID 后需复核 |
| **High** | 缓解措施未完整实现或 SIL 分配无法满足 | 不可接受，需架构级动作或推迟 ODD |

> **v0.1 注**：多数`[HAZID 校准]`项目将产生 Medium 残余风险，待 HAZID RUN-001 (8/19) 完成后在 D3.3 降至 Low 或升级缓解。

### 5.4 关键失效模式示例（供安全工程师参考）

以下是预期填写方向（执行时安全工程师逐条核实）：

**ODD-SM 子系统（6–8 条）：**
- ODD 状态错误转换（如 NOMINAL → CRITICAL 漏触发）
- ODD 状态机卡死（无法响应新输入）
- Conformance_Score 计算溢出（w_E + w_T + w_H 权重和越界）
- ODD 状态输出时间戳过时（stamp > 1s stale）
- ODD 子域边界阈值加载失败（Capability Manifest 读取失败时默认值错误）
- MRC 触发信号发送失败（M7 请求后 M1 仲裁器无响应）
- ODD 越界但仍允许 D3/D4 继续运行（降级判断错误）

**TDL-EST 子系统（5–6 条）：**
- TDL 低估（输出 TDL < 真实可用接管时间）→ 不必要 MRC 触发
- TDL 高估（输出 TDL > 实际 → 推迟 MRC 请求）→ ROC 窗口不足
- TCPA_min 输入数据过时（M2 上次更新 > 2s）
- TMR 计算数值溢出（TCPA 极短时 TMR 趋近于 0 的除法边界）
- TDL 权重系数加载错误（从 Capability Manifest 错读 w_H）

**MSG-SCHED 子系统（4–5 条）：**
- /sil/m1/odd_state 发布超时（DEMO-2 要求 ≤ 200ms 刷新率）
- DDS QoS 冲突（M7 订阅 BEST_EFFORT 但 M1 发布 RELIABLE）
- 消息 schema_version 不匹配（与接收方不兼容时静默丢弃）
- 上游消息（M2/M3）堆积导致最旧数据被处理（FIFO 队列溢出）

**CAP-MFT 子系统（2–3 条）：**
- Capability Manifest 文件缺失（启动时无默认船型参数）
- 参数超出有效范围（如 ROT_max = 0 导致除法错误）

**HLTH-MON 子系统（2–3 条）：**
- 心跳漏检（M2 已失联但 M1 未触发 DEGRADED）
- 误报降级（M2 短暂延迟被误判为失效 → 不必要 ToR 触发）

### 5.5 DC% 估算方法（v0.1）

v0.1 阶段使用专家判断（安全工程师 + 架构师 review）：

| DC% 范围 | 定义 | v0.1 依据 |
|---|---|---|
| ≥ 99% | 自动检测，每次使用前 | 运行时 CRC / watchdog heartbeat |
| 90–98% | 自动检测，周期 < 1s | 周期性自检 + 消息时间戳验证 |
| 60–89% | 自动检测，周期 1–10s | 状态一致性检查 |
| < 60% | 人工/外部检测 | 日志审计 / 外部监控 |

> **IEC 61508-2 要求**：SIL 2 核心路径须 DC ≥ 90%（单通道 HFT=0）；推荐 HFT=1 双通道使 SFF 要求从 ≥ 60% 降至 ≥ 90%（Type A）。v0.1 仅估算，量化验证在 D3.3a 完整 FMEDA。
