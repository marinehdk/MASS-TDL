## 8. Web HMI 增项规格

### 8.1 Apache Arrow IPC 场景回放

**后端（orchestrator）**

- `POST /export/arrow?run_id=X` → 将 MCAP bag 转换为 Arrow IPC 文件
- 转换工具：`tools/vv/mcap_to_arrow.py`（复用 `pyarrow` + `rosbag2_py`）
- 输出格式：`runs/{run_id}/replay.arrow`（列式，每列一个 topic 频道）
- Arrow schema：`{timestamp_ns: int64, channel: str, payload: binary}`

**前端（HTTP range request scrubber）**

- `GET /runs/{run_id}/replay.arrow` with `Range: bytes=...`
- 前端解析 Arrow IPC footer → 定位目标时间戳对应 record batch offset
- GSAP timeline scrubber：拖拽 → range request → 解析 → 渲染，全链路 < 100ms
- 实现位置：`web/src/components/ArrowScrubber.tsx`（新建）

### 8.2 Puppeteer 批量 GIF/PNG 导出

- 脚本：`tools/vv/puppeteer_batch.js`（Node.js + `puppeteer`）
- 输入：50 场景的 `run_id` 列表（JSON）
- 流程：`for each run_id` → 加载 `/report/{run_id}` → Arrow scrubber 回放 → `page.screenshot()` 关键帧 PNG × N + `gif-encoder` 合成 GIF
- 输出：`evidence/{run_id}/scenario.gif` + `evidence/{run_id}/keyframes/*.png`
- DEMO-2 导出：`POST /export/gif-pack` → 触发全 50 场景批量 → `evidence.zip` 下载

### 8.3 Turf.js Grounding Hazard 高亮（DEMO-2 前端实现）

- **检测频率**：10 Hz（与 own-ship state 更新同步）
- **预测时窗**：120s Dead Reckoning（当前 SOG × COG，忽略舵角）
- **实现**：`web/src/utils/groundingDetect.ts`
  - 输入：own-ship `{lat, lon, cog_deg, sog_kn}` + ENC GeoJSON polygons（已由 martin tile server 提供）
  - 计算：Turf.js `lineString` 预测路径 → `booleanIntersects(path, encPolygon)`
  - 输出：`isGroundingRisk: boolean` + `riskPolygonIds: string[]`
- **渲染**：MapLibre GL 图层 `grounding-hazard-highlight`，检测到时 polygon 变红 + 警告 badge
- **Phase 3 升级路径**：scoring_node 后端实现 `/sil/grounding_hazard` topic（SIL 01-architecture §7.3 预留 IDL），前端切为 topic 订阅模式（D3.4）

### 8.4 多目标同屏（≥5 船）

- `target_vessel_node` 已支持多实例，`sensor_mock_node` 已支持多目标
- 前端 `SilMapView` 当前无目标数量硬限制；需验证 ≥5 目标时 MapLibre 渲染 FPS ≥ 30
- 测试场景：`imazu-14-ms.yaml`（3 目标）→ 扩展到 imazu-22-ms（最多目标数）+ 自定义 5 船场景
- 若 FPS < 30：启用 `canvas` 渲染模式替代 DOM marker（GAP-008 已有降级方案）

### 8.5 TLS/WSS 安全

- foxglove_bridge：启用 `--certfile` + `--keyfile` 参数（自签名证书用于开发，Let's Encrypt 用于 DEMO-2）
- orchestrator FastAPI：uvicorn `--ssl-certfile` + `--ssl-keyfile`
- 前端：`wss://` + `https://` 替换 `ws://` + `http://`
- 验证：`openssl s_client -connect 127.0.0.1:8765` 握手成功

## 10. dds-fmu FMI Bridge 集成验证

**延迟实测**（V&V Plan v0.1 §6.1 对齐）：

| 指标 | 预算 | 测量方法 |
|---|---|---|
| dds-fmu P95 latency | ≤ 10 ms | ROS2 topic timestamp → FMU input port ready |
| dds-fmu P99 latency | ≤ 15 ms | 同上，1000 次采样 |
| Max jitter | ≤ 5 ms | 1s 窗口内绝对偏差 |

若 P99 > 15ms，按 V&V Plan §6.1 执行：① QoS reliability buffer depth 增大；② FMI co-sim master jitter buffer 启用；③ 如仍超标 → 上报 Safety 工程师做预算修订。

**1h Crash-Free 测试**：

- 策略：Imazu-22 顺序循环（22 场景无间隙连续 run，约 22 × 10 min = 220 min > 1h）
- 测试栈：own-ship MMG FMU（dds-fmu 桥）+ ROS2 M1–M6（production C++）+ M7（独立进程）
- 终止条件：任意进程 crash / M7 VETO 连续 3 次触发 MRC / 内存 RSS 超过 4GB
- 监控：`tools/vv/crash_monitor.py`（每 5s 采集 RSS + 进程状态 + M7 VETO 事件数）
- 证据：`evidence/1h_crash_free.jsonl`（每 5s 一行：timestamp, rss_mb, veto_count, status）
