## 4. 组件行为规格

### 4.1 CurrentErrorMonitor

**职责**：消费 L4 XTE 和 M2 海流估计，输出 severity 枚举，供 `MissionManagerNode` 填写 `MissionGoalMsg` 字段并决策是否发 ASDR HIGH 告警。

```cpp
enum class CurrentErrorSeverity : uint8_t { NORMAL = 0, MEDIUM = 1, HIGH = 2 };

struct CurrentErrorMonitorConfig {
    float xte_high_nm      = 0.5F;   // XTE > 0.5 nm → HIGH
    float xte_medium_nm    = 0.3F;   // XTE > 0.3 nm → MEDIUM
    float current_high_kn  = 2.0F;   // 海流 > 2.0 kn → HIGH
    float current_medium_kn= 1.5F;   // 海流 > 1.5 kn → MEDIUM
    float l4_stale_s       = 2.0F;   // L4 消息超时 → xte_nm = -1（降级）
};

struct CurrentErrorReading {
    CurrentErrorSeverity severity;
    float xte_nm;          // -1 = L4 不可用
    float sea_current_kn;
    bool  l4_available;
};

class CurrentErrorMonitor {
public:
    explicit CurrentErrorMonitor(CurrentErrorMonitorConfig cfg);
    void update_tracking_error(const TrackingError& msg, TimePoint now);
    void update_world_state(const WorldState& msg, TimePoint now);
    CurrentErrorReading evaluate(TimePoint now) const;
};
```

**severity 判定规则**（两源任意一条满足即取高值）：

| 条件 | severity |
|---|---|
| `xte_nm > 0.5` **或** `sea_current_kn > 2.0` | HIGH |
| `(0.3 < xte_nm ≤ 0.5)` **或** `(1.5 < sea_current_kn ≤ 2.0)` | MEDIUM |
| L4 超时（> 2 s）且海流 ≤ 1.5 kn | NORMAL（xte_nm = -1）|
| 两者均在正常范围 | NORMAL |

**告警触发条件**（`MissionManagerNode` 决策）：

- severity 从 `MEDIUM/NORMAL` 升为 `HIGH` → 立即发 ASDR record（`decision_type = "current_error_high_alert"`, `severity_label = "HIGH"`）+ 发布 `MissionGoalMsg`（含 `current_error_severity=2`，`rationale` 更新）
- severity 从 `HIGH` 降回 → 发 ASDR record（`decision_type = "current_error_resolved"`）
- `HIGH` 期间 `MissionGoalMsg.confidence` 计算顺序：`EtaProjector.confidence × L1WatchdogMonitor.confidence_factor × 0.85`，结果不低于 0.4。（三因子独立相乘；若 L1WatchdogMonitor 已使 confidence ≤ 0.4，current HIGH 衰减不再进一步降低）

> Current error HIGH **不触发 RouteReplanRequest**（mission 继续；M8 告警操作员自行判断）。

### 4.2 L1WatchdogMonitor

**职责**：追踪 L1 VoyageTask 最后接收时刻，输出 watchdog 状态，驱动 `MissionGoalMsg.confidence` 衰减与超时 ToR。

```cpp
enum class L1WatchdogStatus : uint8_t { OK = 0, WARNING = 1, TIMEOUT = 2 };

struct L1WatchdogConfig {
    double warning_s = 60.0;   // 断联 > 60s → WARNING
    double timeout_s = 120.0;  // 断联 > 120s → TIMEOUT → ToR
    float  confidence_warning = 0.6F;  // WARNING 时 confidence 上限
    float  confidence_timeout = 0.4F;  // TIMEOUT 时 confidence 上限
};

struct L1WatchdogResult {
    L1WatchdogStatus status;
    double elapsed_s;
    float  confidence_factor;   // 乘于 EtaProjector 输出
};

class L1WatchdogMonitor {
public:
    explicit L1WatchdogMonitor(L1WatchdogConfig cfg);
    void notify_voyage_task_received(TimePoint now);
    L1WatchdogResult evaluate(TimePoint now) const;
};
```

**状态转移与动作**：

| L1 断联时长 | watchdog_status | confidence_factor | MissionManagerNode 动作 |
|---|---|---|---|
| ≤ 60 s | OK | 1.0 | 无 |
| 60 s – 120 s | WARNING | 0.6 | ASDR WARNING（`decision_type = "l1_dropout_warning"`）；`MissionGoalMsg.l1_watchdog_status = 1`；mission 继续 |
| > 120 s | TIMEOUT | 0.4 | ASDR CRITICAL（`decision_type = "l1_dropout_timeout"`）；发 `ToR_RequestMsg`（`reason = MANUAL_REQUEST`, `deadline_s = 60`）；mission 继续直至 ToR 完成 |
| L1 恢复（任意 VoyageTask 到达）| OK | 1.0 | ASDR INFO（`decision_type = "l1_recovered"`）；`notify_voyage_task_received()` 重置计时器 |

### 4.3 L1/L2 双订阅独立性语义（F P1-F-01 论证）

**设计意图**：L1 VoyageTask = 任务授权令（起终点 + ETA 窗口 + 约束）；L2 PlannedRoute = 执行载体（航点序列 + 速度曲线）。两者功能正交，分别对应"去哪里"与"怎么走"。

**独立性约束表**：

| 场景 | L1 状态 | L2 状态 | M3 行为 |
|---|---|---|---|
| 正常 | 有效 VoyageTask（≤ 60s）| 新鲜 PlannedRoute | ACTIVE，正常 ETA + mission_goal |
| L1 断联 | 最后 VoyageTask > 60s | 新鲜 PlannedRoute | ACTIVE + L1 watchdog WARNING；mission 继续（L2 route 有效）|
| L1 长时断联 | > 120s | 新鲜 PlannedRoute | ACTIVE + L1 watchdog TIMEOUT + ToR；但 mission 执行到 ToR 完成 |
| L2 断联 | 有效 | PlannedRoute > 3s stale | ACTIVE + ETA = -1；`mission_goal.confidence` 降；速度保持上值 |
| 双断联 | > 60s | > 3s stale | L1 watchdog WARNING + ETA 不可用；最终 > 120s → ToR |
| 首次启动 | 无 VoyageTask | 有 PlannedRoute | IDLE（状态机 AwaitingRoute 等 VoyageTask 先到；L2 route 缓存备用）|

**约束**：L1 VoyageTask **必须先于** L2 PlannedRoute 进行校验以激活任务（状态机 IDLE → AWAITING_ROUTE → ACTIVE）。L1 断联后 mission ACTIVE 期间，使用内存中最后一个有效 VoyageTask 的约束（ETA 窗口、目标点），不重新校验。

---

### 4.4 Mission_GoalMsg 发布语义

- **0.5 Hz 周期**：每 2 s 发布一次，填充最新 ETA / confidence / severity 字段
- **立即发布触发条件**（在周期外额外发一条）：
  - `current_error_severity` 状态变化（NORMAL↔MEDIUM↔HIGH 任意跳转）
  - `l1_watchdog_status` 状态变化（OK→WARNING / WARNING→TIMEOUT / 任意→OK）
  - ODD zone 切换（`last_odd_zone` 变化）
  - 收到新 VoyageTask（校验通过后）
- 若多个立即触发条件**同时满足**（如 ODD 切换 + current HIGH 同时发生），合并为**单条** `MissionGoalMsg` 发布（避免同一 timer tick 内重复发出）
- `rationale` 字段格式（SAT-2）：`"[M3] eta=<X>s conf=<Y> xte=<Z>nm cur=<W>kn l1=<status> odd=<zone>"`

---

### 4.5 重规划触发优先链（确认不变）

现有四级优先链（`ReplanRequestTrigger`）**不修改**：

```
MRC_REQUIRED (deadline 30s) > ODD_EXIT_CRITICAL (60s) > ODD_EXIT_DEGRADED (120s) > MISSION_INFEASIBLE (120s) > CONGESTION (300s)
```

`CurrentErrorMonitor` HIGH 告警**不加入**此链（告警 M8，mission 继续，由操作员判断）。`L1WatchdogMonitor` TIMEOUT 触发 `ToR_RequestMsg`（独立路径，不走 ReplanTrigger）。

### 4.6 ODD-B 进入 → RouteReplanRequest（DEMO-2 演示路径）

**触发序列**（端到端，DEMO-2 实时可视）：

```
t=0:     M1 conformance_score 从 0.9 降至 0.55（ODD_A → ODD_B）
t=1s:    ReplanRequestTrigger.check_odd_exit debounce 1s 满足
t=1s:    M3 发布 RouteReplanRequest{reason=ODD_EXIT, deadline_s=120}

t=1s+:   Web HMI SAT-2 面板显示 "ODD-B: RouteReplan Requested @ deadline=120s"

**DEMO-2 验收判据**：录屏或 GIF 显示从 ODD_A 切换到 ODD_B 后 ≤ 2s 内 Web HMI 出现重规划请求标记。

## 5. ETA / 重规划触发条件完整清单

| 触发条件 | 阈值 | 优先级 | 触发 | 动作 |
|---|---|---|---|---|
| MRC envelope state | ENVELOPE_MRC_PREP 或 MRC_ACTIVE | 1（最高）| 即时 | RouteReplanRequest(MRC_REQUIRED, 30s) |
| ODD conformance 急降 | < 0.3（critical）| 2 | 即时 | RouteReplanRequest(ODD_EXIT, 60s) |
| ODD conformance 缓降 | < 0.7（degraded）持续 1s | 2 | 1s debounce | RouteReplanRequest(ODD_EXIT, 120s) |
| ETA 超期 | eta_to_target_s > eta_window.latest + 600s | 3 | 0.5Hz 周期 | RouteReplanRequest(MISSION_INFEASIBLE, 120s) + speed_recommend = max |
| ETA 过早 | eta_to_target_s < eta_window.earliest | 3 | 0.5Hz 周期 | RouteReplanRequest(MISSION_INFEASIBLE, 180s) |
| 重规划次数溢出 | replan_attempt_count ≥ 3 | 4（最低）| 即时 | RouteReplanRequest(CONGESTION, 300s) |
| L1 watchdog TIMEOUT | L1 断联 > 120s | 独立路径 | 超时 | ToR_RequestMsg(MANUAL_REQUEST, 60s) |
| Current error HIGH | XTE > 0.5 nm 或 海流 > 2.0 kn | 监控（不触发 replan）| 即时 | ASDR HIGH + MissionGoal.current_error_severity=2 |
| 重规划 deadline 到期 | REPLAN_WAIT 超时 | 级联 | deadline 耗尽 | ToR_RequestMsg(ODD_EXIT, 60s) |

## 6. 降级路径（DEGRADED / CRITICAL / OUT-of-ODD）

| 状态 | 条件 | M3 行为 | current_error_severity | l1_watchdog_status |
|---|---|---|---|---|
| ACTIVE normal | 所有输入新鲜，ODD ≥ 0.7 | 正常周期 mission_goal | NORMAL | OK |
| ACTIVE + current HIGH | XTE > 0.5 或 cur > 2.0 kn | mission 继续 + ASDR HIGH + M8 alert | HIGH | OK |
| ACTIVE + L1 WARNING | L1 断联 60–120s | mission 继续；confidence ≤ 0.6 | 不变 | WARNING |
| ACTIVE + L1 TIMEOUT | L1 断联 > 120s | mission 继续直至 ToR; confidence ≤ 0.4 | 不变 | TIMEOUT |
| REPLAN_WAIT | ODD exit 或 infeasible | 保持现 route; L2 deadline 倒计时 | 不变 | 不变 |
| OUT-of-ODD | M1 超时 > 2s | 假设 ODD-C；ToR(SAFETY_ALERT, 30s) | 不变 | 不变 |

通过条件：步骤 1–6 全通，且 HIGH 触发 → MissionGoal 发布 ≤ 100ms。
```
