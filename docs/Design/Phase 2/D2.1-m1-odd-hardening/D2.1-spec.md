## 2. 候选方案

### 方案 A：手术式扩展（Surgical Extension）🟢 选定

在现有 types.hpp + odd_state_machine 上做最小增量。不重构 FSM 核心逻辑，通过扩展输入/输出结构实现全部 DoD。

| 维度 | 做法 |
|---|---|
| ODD 子域 × 健康矩阵 | 现有枚举已在 types.hpp。在 `OddStateMachine::step()` 中增加 zone/health 感知分支（不新增状态）|
| conformance_score | 实现 ConformanceScoreCalculator 三轴 → 单值加权 + EMA 平滑（τ=5s）|
| ToR 矩阵 | ParameterSet 新增 tor_matrix，TmrTdlEstimator 查表返回 TMR |
| Capability Manifest | 通过 parameter_loader 加载，ROT_max(u) 调用 common/capability_manifest.py |
| FMEDA | 独立 Markdown（docs/Design/Safety/FMEDA/M1-FMEDA-v0.1.md）|
| IDL 升级 | 现有 topic 追加字段，新增 tor_request topic |

**置信度**：🟢 — 改动量 ~600-800 LOC，PATH-S 不破，5.0 pw 充裕。

### 方案 B：矩阵驱动 FSM 重构（Matrix-Driven FSM）

将 6 状态 FSM 重构为 4×3=12 态显式矩阵。更形式化可验证，但改动 ~300 LOC 侵入 FSM 核心，违反 Karpathy 第 3 条（surgical changes）。🟡 弃用。

### 方案 C：分层 FSM（Layered FSM）

保留外层 6 状态 + 新增内层 zone×health tracker。架构合理但增加复杂度（两层 FSM 竞态风险）。🟡 弃用。

### 决策理由

方案 A 被选定因为：① 严格遵循 Karpathy 第 3 条——现有 types.hpp 已含所有需要的枚举和结构体，只需"激活"；② 5.0 pw 中 1.5 pw 留给 FMEDA + 测试 + IDL，3.5 pw 代码实现充裕；③ D3.5 HAZID 8/19 会回填参数，当前不需重 FSM 架构。

## 3. 选定方案详细设计

### 3.1 状态机设计

**保持 6 状态 FSM 不变**（In / Edge / Out / MrCPrep / MrCActive / Overridden），`step()` 扩展为感知 zone + health：

```cpp
EnvelopeState step(double score, double tdl_s, double tmr_s,
                   EventFlags events, OddZone zone,
                   SystemHealth health, TimePoint now) noexcept;
```

**zone/health 感知分支**（手术式追加到 `compute_next()`）：

| 条件 | 行为 |
|---|---|
| `health == Critical` | 直接触发 MrCPrep（不经过 EDGE/OUT）|
| `zone == ODD_C && score < 0.6` | EDGE→OUT 阈值收紧到 0.6（港内容错更小）|
| `health == Degraded` | score × stale_degradation_factor（现有 types.hpp 已有）|
| M7 Safety_Alert 到达 | 立即 MrCPrep（方案 A 仲裁：Checker VETO > Doer）|

**合法状态组合**（架构报告 §5.3.2 查表落实）：

| AutoLevel | OddZone | SystemHealth | 许可 |
|---|---|---|---|
| D4 | ODD_A only | Full only | ✅ |
| D3 | A/B/D | Full/Degraded | ✅ |
| D2 | ALL | ALL | ✅ |
| 任何 | 任何 | Critical | → MrCPrep 强制 |

**新增类型**（types.hpp 追加）：

```cpp
struct OddZoneHealthPair {
  OddZone zone;
  SystemHealth health;
};
```

### 3.2 Conformance Score 三轴融合

```
Conformance_Score(t) = w_E × E_score(t) + w_T × T_score(t) + w_H × H_score(t)

权重（架构报告 §3.6，现有 ParameterSet 已含）：
  w_E = 0.4 [TBD-HAZID]
  w_T = 0.3 [TBD-HAZID]
  w_H = 0.3 [TBD-HAZID]

阈值：
  > 0.8 → IN
  0.5–0.8 → EDGE
  < 0.5 → OUT → MRC 序列
```

**各轴评分逻辑**：

| 轴 | 输入 | 评分规则 | 阈值来源 |
|---|---|---|---|
| E_score | visibility_nm, sea_state_hs | 查 EScoreThresholds 双线性插值 → [0,1] | types.hpp 已有 |
| T_score | gnss/radar/comm 健康 | 全绿=1.0 / 部分降质=0.6 / 关键故障=0.3 | TScoreThresholds 已有 |
| H_score | tmr_available, comm_ok | 可用=1.0 / 不可用=0.5 | HScoreThresholds 已有 |

**EMA 平滑**（抑制 ODD 切换跳变）：

```
Conformance_Score_filtered(t) = α × score_raw(t) + (1-α) × score_filtered(t-1)
α = Δt / τ, τ = 5s [TBD-HAZID]
```

CCS 白盒可审计——EMA 是确定性滤波器，非 ML。

### 3.3 TMR/TDL 实时计算

```
TMR = lookup_tor_matrix(assumed_operator_state)
TDL = min(TCPA_min × 0.6, T_comm_ok, T_sys_health)

安全约束：TDL > TMR 必须成立
TDL ≤ TMR → 立即触发 tor_request + MRC 准备
```

**TDL 子项**（架构报告 §3.4）：

| 子项 | 含义 | 来源 |
|---|---|---|
| TCPA_min × 0.6 | 最近威胁 CPA 时间 × 60%（40% 余量给操作员）| M2 world_state |
| T_comm_ok | 预计通信链路可用时长 | 通信健康监控 |
| T_sys_health | 系统可靠维持时间（基于 MTTF 估算）| SystemHealthSnapshot |

### 3.4 ToR 自适应矩阵

| assumed_operator_state | TMR (s) | 实证依据 |
|---|---|---|
| `Bridge_OnDuty` | **30** | Fjørtoft & Rødseth 2020 层级 2（驾驶台持续监督）；⚠️ 低于 Veitch 60s 基线，FMEDA 标注为假设失效风险 |
| `Bridge_Nearby` | **60** | Fjørtoft & Rødseth 2020 层级 3（驾驶台附近）+ Veitch 2024 基线 |
| `ROC_Attended` | **60** | Veitch 2023 n=32 实验：60s 显著优于 20s |
| `Mess_Rest` | **90** | Rødseth C1/C2 层间插值（餐厅→驾驶台物理移动 ~2-3min，含穿衣+行走）|
| `Cabin_Sleep` | **120** | Rødseth 2021 C1 层级（操作员在舱室，需 5-10min 穿衣+行走+态势感知恢复）|

**实现**：`ParameterSet.tor_matrix` 字段（YAML 可加载），`TmrTdlEstimator` 查表。

### 3.5 Capability Manifest 集成

**单源真相链**：

```
Parameter Database (船厂提供, CCS 签名)
       │ 写入
       ▼
l3_external_msgs/CapabilityManifest (DDS topic)
       │ M1 订阅
       ▼
parameter_loader → ParameterSet.rot_max_curve[]
       │
       ▼
M1 ROT_max(u) 查询 → /l3/m1/odd_state.rot_max_current
```

**手术式改动**：
- 现有 `common/capability_manifest.py` 已实现 `rot_max(speed_kn)` 线性插值
- M1 `ParameterSet` 已有 rot_max_curve 字段 → `parameter_loader` 补充解析逻辑
- Manifest 缺失时 M1 启动失败 → DEGRADED（不做 fallback 默认值）
- **严禁 hardcode** ROT_max

### 3.6 M1/M7 Doer-Checker 仲裁

**选定方案**：M7 VETO 直接覆盖 M1（方案 A）。

- M7 发布 `Safety_AlertMsg(severity=CRITICAL, mrc_required=true)` → M1 立即切换 MrCPrep
- M1 不经过自身 FSM 判断，Checker 权威 > Doer
- M1 的 own judgement 作 SAT-2 rationale 记录但不阻挠 M7
- M7 心跳丢失 → M1 自动 DEGRADED（500ms 超时）

## 5. 降级路径

| 触发条件 | M1 行为 | 下游影响 |
|---|---|---|
| **DEGRADED**（任一传感器降质，Conformance_Score ∈ [0.5,0.8]） | odd_state.health=DEGRADED；score × stale_degradation_factor；不触发 MRC | M4 行为集收窄 / M5 速度上限降低 / M8 SAT-2 标注降级原因 |
| **CRITICAL**（关键传感器失效 或 M7 VETO 到达） | 直接进入 MrCPrep；odd_state.health=CRITICAL | M4/M5 停止规划 / M8 显示接管倒计时 |
| **OUT_of_ODD**（Conformance_Score < 0.5） | 若 TDL > TMR：先发 tor_request→MrCPrep；若 TDL ≤ TMR：直接 MrCActive | M7 监督 MRC 执行 / M8 通知 ROC |
| **Capability Manifest 缺失** | M1 启动失败，不进 IN 状态 | 全系统等待 Manifest 加载 |
| **M7 VETO 到达** | 立即 MrCPrep，不经过自身 FSM 判断 | Checker 权威 > Doer |
| **M7 心跳丢失** (>500ms) | M1 自动 DEGRADED | 失去安全网 → 升级告警到 M8 |
| **M2 输入 stale** (>2s) | Conformance_Score × stale_degradation_factor | E_score / TDL 依赖 M2 数据降质 |

### IEC 61508 SIL 2 论证

- M1 模式仲裁 + MRC 触发 = **核心安全功能** → SIL 2
- **Route 1H**（SFF + HFT 表驱动）— 缺乏 Route 2H 所需 1 亿小时现场数据
- **B 类设备**（Jetson 边缘计算）：目标 SFF ≥ 99%（HFT=0） 或 SFF ≥ 60%（HFT=1）
  - 推荐 HFT=1 架构：M7 作为独立 Checker 通道（异构硬件 + 独立代码库）
- **ISO 21448 SOTIF**：M1 本身不使用 ML，SOTIF 风险低；但消费 M2（含 ML 感知）输入 → 通过 `confidence` 字段标注输入不确定度

## 8. 参数锁定策略（应对 R2.G）

132 [TBD-HAZID] 参数 8/19 才闭口。D2.1 在 7/31 前锁定以下**行为分支结构敏感参数**初值：

| 参数 | 初值 | 敏感原因 | HAZID 校准方式 |
|---|---|---|---|
| w_E / w_T / w_H | 0.4 / 0.3 / 0.3 | 改变三轴相对权重会改变 ODD 判定结果 | FCB ≥100h 运营数据贝叶斯回归 |
| IN→EDGE / EDGE→OUT 阈值 | 0.8 / 0.5 | 阈值偏移直接改变 MRC 触发频率 | 场景仿真 ROC 曲线校准 |
| TMR 矩阵（5 值） | 30/60/60/90/120 | Bridge_OnDuty=30s 低于基线，风险最高 | 实船接管实验（≥5 名船长）|
| EMA τ | 5s | τ 过长→降质响应延迟；τ 过短→假性切换 | 传感器噪声实测 PSD 分析 |
| tcpa_coefficient | 0.6 | TCPA 余量决定 TDL 计算 | Veitch 2024 + FCB 制动曲线联合校准 |

非结构敏感参数（visibility/sea_state 阈值、comm_delay_ok_s 等）沿用现有 defaults，HAZID 后 D3.5 统一回填。
