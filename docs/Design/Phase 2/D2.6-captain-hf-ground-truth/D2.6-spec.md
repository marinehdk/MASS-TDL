## 1. 目的

D2.6 为系统提供**船长心智模型 ground truth**，作用于三个方向：

1. **M8 设计校准**：访谈结果注入架构 v1.1.3 stub §12.3（差异化视图 · 心智模型）和 §12.5（培训资质），确保 SAT-1/2/3 三层信息的呈现方式符合实际船员认知模型，而非工程师假设
2. **可用性验证基线**：Figma 原型 + 桌面可用性测试（n ≥ 5）在 DEMO-2（7/31）前建立"决策透明性理解度"指标的原始数据集
3. **培训框架接口**：产出胜任力矩阵草案，作为 D3.5' 完整培训课程大纲的输入骨架

## 3. 背景与架构关联

### 3.1 M8 设计基础（架构 v1.1.3-pre-stub §12）

M8（HMI/Transparency Bridge）是系统中唯一对 ROC 操作员和船上船长说话的实体。其核心设计：

- **SAT-1/2/3 三层透明性**（§12.2）：SAT-1 全时展示；SAT-2 按需触发（COLREGs 冲突 / M7 告警 / 操作员请求）；SAT-3 基线 + TDL < 30s 自动优先
- **差异化视图**（§12.3）：ROC 操作员（完整数值量化 + 完整规则链）vs 船上船长（直觉可视化 + 高层摘要）
- **ToR 协议**（§12.4）：60s 时窗 [R4]；"已知悉 SAT-1" 交互验证机制（§12.4.1）
- **透明度悖论**（§12.2 注记）：全层同时展示 SAT-2 反而升高认知负荷 [R5-aug]——本 D 访谈需验证此发现在 FCB 船长群体中的适用性

§12.3 差异化视图的**当前设计基于工程师假设**，缺乏实际船员访谈数据支撑。D2.6 产出将直接回填 v1.1.3 stub §12.3（心智模型 ground truth）和 §12.5（人员资质/培训/演练）。

### 3.2 Web HMI 现状（D1.3.2.3）

D1.3.2.3 已实装 Production-grade Web HMI：
- 技术栈：React + MapLibre GL JS (WebGL) + foxglove_bridge
- 标准：**IEC 62288:2021 AMD1:2024** SA subset + **IMO MSC.1/Circ.1609 (2019)** S-Mode
- 已有 SAT-1/2/3 stub topic (`/l3/sat/data @1Hz`)
- Figma 原型须与此实装的视觉风格和信息层级保持一致（v3.1 新增项 (g)）

### 3.3 监管空白

🟡 **BNWAS（IMO MSC.282(86)）在 MASS 自主模式下无直接对应规则**：IMO RSE 2021 Regulatory Scoping Exercise 确认此监管空白；SOLAS 和 STCW 正在修订中（预计 2026-2028 完成）。CCS 规范已要求远程控制站必须接收船舶机械告警，且告警沉默机制须独立 [NLM-global: BNWAS/MASS]。本 D 的 BNWAS 等效设计须记录"监管空白"这一背景并选择保守合规路径。

## 4. 设计决策（brainstorming 2026-05-21）

### 4.1 访谈协议 — 混合模式

**决策**：采用 **30 min 半结构化 + 15 min SAT-2 think-aloud** 混合协议，每次访谈总时长约 50 min（含暖场 + 收尾）。

**理由**：
- 前半段（半结构）：建立对船长实际操作思路的无偏见理解——视野分布 / 扫视模式 / 注意力优先级 / ToR 经验；避免先展示系统影响自然行为报告
- 后半段（SAT-2 think-aloud）：展示一段真实 COLREGs 冲突场景（SAT-2 已激活），请船长实时说出"你先看哪里？你理解系统为何这样动作吗？"直接采集 v3.1 (h) 要求的**决策透明性理解度**数据
- 工业实践支撑：Wärtsilä IntelliTug 项目中 Tug Master 直接参与测试用例设计，确认资深船长的 think-aloud 输出具有高 ground truth 价值 [NLM-global: HF-interview]

**访谈 Topic Guide（半结构部分）**：

```
T1. 常规航行（Transit）：您最频繁检查的信息是什么？检查顺序？
T2. 目标船接近（COLREGs 场景）：您第一眼看哪里？多久关注一次？
T3. 异常 / 接管决策：有没有您希望系统"早点告诉你"的信息？格式是？
T4. 系统辅助经历：如果有自动避让系统，您想知道它"为什么这样做"到什么程度？
T5. ROC 视角（如适用）：岸基操作员和桥楼船长对信息需求有何不同？
```

**Think-aloud 刺激材料**：D1.3.2.3 Web HMI + Imazu head-on 场景（DEMO-1 后即可用），确保 SAT-2 colregs_chain 可见。

### 4.2 Figma 双视图 — 方向 A 对称骨架 + 风格差异层

**决策**：单套 Figma frame，通过**角色切换层**实现差异化：
- 船长视图：暖色系（#E8F5E9 / #FF8F00）/ 大字体（≥16px 主信息）/ 罗经图 / 直觉状态卡片 / 一键接管按钮
- ROC 视图：冷色系（#E3F2FD / #1565C0）/ 密集数值表格 / 完整规则链 / 分步确认 ToR

**IEC 62288 SA subset 边界**（与 D1.3.2.3 对齐）：

| 显示要素 | 船长层 | ROC 层 | 标准依据 |
|---|---|---|---|
| 当前自主等级（D2/D3）| ✅ 大图标 | ✅ 文字 + 数值 | IEC 62288:2021 [R35-§TBD] |
| ODD 子域 + Conformance | ✅ 颜色指示 | ✅ 数值 + 百分比 | IEC 62288:2021 [R35-§TBD] |
| 目标船威胁列表 | ✅ Top-3 直觉卡片 | ✅ 完整列表（CPA/TCPA/conf）| IEC 62288:2021 [R35-§TBD] |
| SAT-2 决策推理 | ✅ 高层摘要（1 句话）| ✅ 完整规则链（Rule N → action）| IEC 62288:2021 [R35-§TBD] |
| ToR 接管界面 | ✅ 一键接管 + 情境总结 | ✅ 分步确认 + 系统状态详情 | IMO MSC.1/Circ.1609 [R-IMO-SMODE] |

**推迟项**（Phase 3+ spawn_task）：完整差异化双 frame——船长专用 Figma 文件（纯航海语言，独立 IEC 62288 §6.4 验证）。

### 4.3 可用性测试招募 — 三级 Fallback

**目标**：n ≥ 5（含 ≥3 FCB + 1 拖船 + 1 渡船）；PM 5/20 起已预约。

**Fallback 顺序**：

| 优先级 | 来源 | 最低要求 |
|---|---|---|
| ① | FCB 在职船长 / 大副（首选）| ≥2 年近岸运营经验 |
| ② | 外部资深船长（航海院校 / 船东协会 / HAZID 干系人网络）| ≥OOW 证书 + ≥5 年当值经验 |
| ③ | R/V Gunnerus 公开访谈资料（NTNU）| HF 咨询核实资料充分性 |

**注**：fallback ③ 仅用于补足访谈数量，不替代签字认可（签字必须来自 ① 或 ②）。

### 4.4 BNWAS 等效机制 — 双轨 A+B 可切换

**决策**：实现 `bnwas_mode` 三态可配置，两套记录同步写入 ASDR：

```yaml
# docs/Design/HF/03-bnwas-design/bnwas-design-draft.yaml（D2.8 stub 输入）
bnwas_mode: DUAL  # HEARTBEAT | SAT1_EQUIV | DUAL
heartbeat:
  interval_s: 180       # 3 分钟，对齐传统 BNWAS A 级
  grace_period_s: 30
  alarm_escalation: [AUDIO_LOCAL, AUDIO_ROC, MRC_PREPARE]
sat1_equiv:
  reset_triggers:
    - tor_acknowledgment_clicked
    - sat1_panel_interaction
    - mode_switch_confirmed
  timeout_s: 300         # SAT-1 等效窗口略宽松（5 分钟）
  alarm_escalation: [AUDIO_ROC, MRC_PREPARE]
asdr_record:
  heartbeat_events: true
  sat1_interaction_events: true  # 已有 §12.4.1 记录基础
```

**合规论证路径**：

| 模式 | CCS 合规路径 | 论证工作量 |
|---|---|---|
| HEARTBEAT | 直接对应 MSC.282(86) + CCS 远控站告警规范 | 低（直接映射）|
| SAT1_EQUIV | 需论证"SAT-1 交互 = 有意味的人为干预"（IMO MASS Code §3.x）| 高（需 D3.9 RFC-007 cyber 联动）|
| DUAL | CCS 可选择任一轨道作为合规依据 | 中（提供最大灵活性）|

**监管空白标注**：IMO MSC.282(86) 明确不适用于无人值守模式；MASS 下的等效机制设计属原创工程实践，待 SOLAS/STCW 修订后对齐 🟡。

### 4.5 培训胜任力矩阵 — 粗粒度接口

**决策**：以 STCW Table A-II/1（OOW 二副/值班驾驶员）为基线，标注 MASS D2/D3 下语义变化的能力项，新增 ROC 专项 ≥5 条；三列（初始训练方法 / 复训周期 / 评估准则）留 `[TBD-D3.5']`，明确作为 D3.5' 输入接口。

**ROC 新增能力项（v0.1 草案，基于 STCW/MASS 研究 [NLM-global]）**：

| # | 能力项 | 对应 STCW 基线条目 | MASS D2/D3 语义变化 |
|---|---|---|---|
| ROC-01 | SAT-2 决策链解读 | A-II/1 §1（看）→ §2（判）| 新增：从规则链（Rule N → action）推断系统意图 |
| ROC-02 | ToR 启动判断与交互验证 | A-II/1 §4 紧急操纵 | 新增：60s 时窗内 + "已知悉 SAT-1" 完整流程 |
| ROC-03 | 自动化偏见识别与主动验证 | A-II/1 §1 瞭望 | 新增：识别 AI 过度信任 / 不足信任场景并主动核实 |
| ROC-04 | BNWAS 等效确认操作 | A-II/1 §3 值班交接 | 新增：heartbeat 响应 / SAT-1 等效交互的合规执行 |
| ROC-05 | ODD 边界识别与降级响应 | A-II/1 §2 安全航行 | 新增：识别 ODD-C/D → 触发 MRC 准备的判断流程 |
| ROC-06 | 网络安全事件下的手动接管 | — | 新增（IACS UR E26/E27 要求）[TBD-D3.9] |
