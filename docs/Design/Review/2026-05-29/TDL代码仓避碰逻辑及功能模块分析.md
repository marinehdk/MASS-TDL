### 1. TDL代码仓避碰逻辑及功能模块分析

根据架构文档，L3 Tactical Decision Layer (TDL) 包含8个核心模块，避碰和回归航路的完整生命周期主要由以下几个模块协同完成：

- **M2 World Model (世界模型)**：负责提供本船与目标船的状态及环境数据。
- **M6 COLREGs Reasoner (避碰规则推理机)**：负责判断相遇态势（如截图中显示的 HEAD-ON 对遇、STAND-ON 直航、OVERTAKING 追越扇区）。
- **M4 Behavior Arbiter (行为仲裁器)**：核心状态机，负责在“循迹/航行 (TRANSIT)”和“避碰 (Collision Avoidance)”等行为状态之间进行切换。代码提交记录中明确提到了行为字段存在 `"TRANSIT"` 状态。
- **M5 Tactical Planner (战术规划器)**：负责生成具体轨迹，采用基于模型预测控制（Mid-MPC + BC-MPC）的算法。
- **M3 Mission Manager (任务管理器)**：负责管理全局航路和当前任务状态。

#### 完整的算法逻辑流（相遇 -> 避碰 -> 回归）

1. **相遇检测**：M2 发现目标，M6 结合相对方位判断为 Head-On（对遇）。
2. **避碰触发**：M4 行为仲裁器将系统状态从 `TRANSIT` 切换为避碰状态。M5 战术规划器 (MPC) 结合避让惩罚函数，生成向右（右舷）转向的局部轨迹。
3. **安全解除**：当目标船驶过且达到安全距离（CPA/TCPA满足阈值）后，M6 取消危险标志，M4 将状态切回 `TRANSIT`。
4. **回归航路**：在 `TRANSIT` 状态下，M5 (MPC) 的代价函数 (Cost Function) 开始重点惩罚**横向拉偏误差 (Cross-Track Error, XTE)**，引导船舶重新贴合原始计划航线。

### 2. imazu-01-ho 场景失效分析（不回归原始航路）

**现象确认**：从您提供的截图可以看到，本船（OWN SHIP）前方有一条黄色虚线（原始计划航路），而蓝绿色虚线（实际轨迹）显示本船已经成功向右进行了避碰机动，但目前**正在与原始航线保持平行航行，没有切回黄色虚线的趋势**。

结合代码库近期的提交记录，导致“会避碰但不会回归原始航路”的核心原因可能出在以下三个维度，建议您在后续调研中重点排查：

#### 怀疑一：M5 规划器的代价函数（Cost Function）权重失衡

在MPC（模型预测控制）算法中，轨迹的生成依赖于代价函数的最优化。当本船处于平行于原航路的状态时，其**航向误差（Heading Error）为0**，但**横向误差（Cross-Track Error, XTE）较大**。

- **原因推测**：如果 M5 的 `TRANSIT` 代价函数中，对航向变化的惩罚权重远大于对横向拉偏的惩罚权重，MPC为了保持“平稳”，就会选择一直平行开下去，而不愿打舵回归航线。
- **佐证**：非常巧合的是，在最近的代码提交记录中，有一条是 `fix(l3): optimize transit utility function using a 5-tier gradient to…`（优化TRANSIT效用函数，使用5层梯度）。这说明开发团队正在频繁调整航行状态下的效用/代价函数。
- **排查方案**：检查 M5 模块中 `TRANSIT` 状态下的 MPC 权重配置，尝试调大横向误差（XTE）的权重，或调小打舵/航向变化的惩罚。

#### 怀疑二：M4 行为仲裁器（Behavior Arbiter）状态卡死

- **原因推测**：系统虽然在物理上已经避开了目标船，但 M6 或 M4 计算的“安全解除阈值”设置得过于保守（例如要求距离目标船极远才算安全）。这会导致 M4 的状态机一直停留在“避碰/偏航”模式，没有成功切换回 `"TRANSIT"` 模式。
- **排查方案**：查看运行日志，监控 M4 模块输出的当前行为状态。如果避碰结束后状态依然不是 `TRANSIT`（提交记录中修复过该字段的类型错误），则需要检查 M6 的危险解除判断逻辑（Clearance Logic）。

#### 怀疑三：M3 任务管理器（Mission Manager）的预瞄点（Lookahead Point）逻辑问题

- **原因推测**：很多循迹算法（如Pure Pursuit或基于LOS的算法）依赖于在黄色虚线上寻找一个“预瞄点”。如果预瞄距离（Lookahead distance）设置得过大，或者当船舶偏离航线较远时，M3 给出的预瞄点直接跳到了航线非常靠后的位置，M5 生成的轨迹就会呈现出一个极度平缓的切入角，在视觉上看起来就像是“平行不回归”。
- **佐证**：提交记录中提到了 `feat(m3_mission_manager): implement Task 3 task_validity substate and…`，说明 M3 的任务和航路状态逻辑正在被修改。
- **排查方案**：在 ROS2 环境或 HMI 调试界面中，可视化出 M3 输出给 M5 的“当前追踪路点（Target Waypoint）”或“预瞄点”，观察它是否因为距离太远而无法引导车辆快速回归。
