### 3.2 N/A 格点声明（应急逻辑）

V&V 工程师维护 `cube_na_declarations.yaml`，每条声明须含：(a) rule + odd + disturbance + seed，(b) 物理无意义的原因，(c) V&V 工程师签字日期。

**立方体 11 Rule 轴**（D1.7 §2.1 锁定）：Rule 5/6/7/8/9/13/14/15/16/17/19。Rule 10（TSS）不在轴内，TSS 场景通过 Rule 9（Narrow Channel）映射覆盖。

已知候选 N/A 类别（运行前识别，运行后验证）：

| Rule | ODD | 理由 | 估计 N/A cells |
|---|---|---|---|
| Rule 9（Narrow Channel）| open_sea | 开阔水域无狭窄航道，场景几何无效 | 1×1×5×5 = 25 |

其余 N/A 候选在 cube_runner 执行后由 V&V 工程师根据实际场景生成结果追加声明（如 Rule 19 × bf_0_1 在某些 ODD 下的物理可行性），每条须附物理无意义理由并签字。

覆盖率计算：
```python
valid_cells = 1100 - na_cells          # 分母扣除 N/A
coverage = hit_cells / valid_cells      # ≥ 0.80 = DEMO-3 hard gate
```

若 coverage < 0.80 且排除已知 N/A 后仍不足，V&V 工程师追加 N/A 声明并记录于 `cube_na_declarations.yaml`，最终覆盖率以有效格点计算为准。

### 5.2 产出指标

| 指标 | 格式 | 目标 |
|---|---|---|
| Pass rate 95% CI | `[lower, upper]` Bootstrap（N_resample = 10000）| lower bound ≥ 90% |

## 6. intelligent_vessel（IV）多船场景

### 6.1 IV 模式设计

IV 模式使 target vessel 具备 COLREGs 感知的机动能力，用于测试 own-ship 在 Rule 16（让路）和 Rule 17（保向）场景下的双向博弈响应。

**运动学模型**：Nomoto 1 阶模型（IMO 机动标准 [R39]）

```python
# 1-DOF Nomoto yaw model
# τ · ṙ + r = K · δ
# τ (time const): FCB 默认 30 s；K (gain): 0.15 [TBD-HAZID-maneuvering]
# Surge: du/dt = (u_des - u) / T_surge；T_surge = 60 s

class NomotoVessel:
    def step(self, dt: float, delta_cmd: float, u_cmd: float) -> ShipState:
        self.r += dt * (self.K * delta_cmd - self.r) / self.tau   # yaw rate
        self.psi += dt * self.r                                     # heading
        self.u += dt * (u_cmd - self.u) / self.t_surge             # surge
        return self._update_position(dt)
```

**避让逻辑（COLREGs 角色驱动）**：

| IV 角色 | 逻辑 | 适用规则 |
|---|---|---|
| `give_way` | VO cone 计算 → 选最近可行速度向量绕行；绕行幅度 ≥ 30°（Rule 8 要求）| Rule 16 |
| `stand_on` | 恒向恒速；in extremis 阈值（CPA < 0.1 NM）触发 Rule 17b 紧急行动 | Rule 17 |
| `non_compliant` | 50% 概率不响应（测试 own-ship 在 IV 违规时的 Rule 17 保向能力）| Adversarial 类 |

**场景 YAML 扩展**（在 maritime-schema `metadata` 节中）：
```yaml
metadata:
  colreg_rule: Rule16
  intelligent_vessel:
    target_id: ts1
    role: give_way           # give_way | stand_on | non_compliant
    nomoto_K: 0.15
    nomoto_tau: 30.0
    t_surge: 60.0
    vo_dcpa_threshold_nm: 0.5  # IV 开始避让的 DCPA 阈值
```

### 6.2 场景套件组成（≥50 场景）

| 子类别 | 数量 | 内容 |
|---|---|---|
| Rule 16 单船让路 | 15 | IV(give_way)；覆盖 ≥3 ODD × 5 初始方位扇区（bow/beam/quarter/stern/ambiguous）|
| Rule 17 单船保向 | 15 | IV(stand_on)；覆盖 ≥3 ODD × 5 初始方位扇区 |

- 自船 + 目标船位置（船形符号，heading 箭头）

**证据链**：
```
filename: {scenario_id}_{asdr_hash[:16]}.gif
          ↑ 可追溯到 cube_results.csv 的 scenario_id 行
```

### 8.2 60:25:15 比例实现

Adversarial:Nominal:Boundary = 60:25:15 是内部启发式，非外部标准（声明同 D1.7 §7.2）。

在 `cube_runner` 中按 seed 分配：
- seed_1 / seed_2：Nominal（farn LHS 生成，AIS 统计分布）

## 11. 降级路径（N/A 应急流程）

```
覆盖率 < 80%？
  ├─ 已声明 N/A 格点可解释？
  │    YES → 重新计算 coverage = hit / (1100 - na_cells)；若 ≥ 80% → 通过
  │    NO  → 追加 N/A 声明（物理无意义理由文档化）→ 重算
  └─ 重算后仍 < 80%？
       → 上报 V&V 工程师 → 决定是否延至 9/30 闭口窗口（master plan 闭环路径）
       → 禁止：减少 seed 数（统计显著性不足，不接受于 CCS 证据包）
```
