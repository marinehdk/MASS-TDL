### 2.2 仲裁 Pipeline（每周期 250ms @ 4Hz）

```
Step 1: 输入快照聚合
  └─ 收集 5 个订阅的最新消息 → ArbitrationInputs

Step 2: 输入超时检查
  └─ 每个消息源的 age ≤ 阈值 → HealthState{Normal, Degraded, Critical}

Step 3: 行为激活筛选
  └─ ODD-aware 字典过滤 + 行为专属激活谓词 → active_set

Step 4: 权重集选择
  └─ HealthState → 权重集{NORMAL, DEGRADED, CRITICAL} → WeightedFunction[]

Step 5: IvP 硬约束构建
  └─ M6 heading_allowed_ranges + ODD speed_bounds + CPA thresholds → IvPHardConstraints

Step 6: IvP 求解
  └─ Two-pass grid search over ψ×u → IvPSolution (or nullopt)

Step 7: 行为优先级仲裁
  └─ IvP 结果 + active_set → primary behavior (MRC 覆盖规则)

Step 8: 输出组装
  └─ ArbitrationResult → Behavior_PlanMsg + ivp_contributions[]

Step 9: ASDR 写入
  └─ 行为变化 / 求解失败 / ODD 跳变 → ASDRRecord
```

### 3.5 ivp_contributions[] 规范


| 索引 | direction_deg | 描述 |
|---|---|---|
| 0 | 0° (N) | 正北 |
| 1 | 45° (NE) | 东北 |
| 2 | 90° (E) | 正东 |
| 3 | 135° (SE) | 东南 |

## 4. 行为字典

### 4.1 行为枚举（v1.1.3 精简为 5 行为）

| ID | 枚举 | 名称 | 适用 ODD | 默认权重 [TBD-HAZID] | 优先覆盖规则 |
|---|---|---|---|---|---|
| 0 | TRANSIT | 航路跟随 | A, B, C | 0.30 | 无 |
| 1 | COLREG_AVOID | COLREGs 避碰 | A, B, D | 0.70 | 无 |
| 2 | RESTRICTED_VIS | 能见度不良 | D | 0.60 | 与 COLREG_AVOID 共存时权重叠加 |
| 3 | CHANNEL_FOLLOW | 狭水道跟随 | B | 0.50 | 无 |
| 4 | MRC_DRIFT | 应急漂航 | **任何** | **1.00** | **始终最高优先级，冻结 IvP 输出** |

> **注**：v1.1.2 架构报告列 8 行为（含 DP_Hold / Approach / Crew_Transfer_Standby / Berth），旧 salvage 代码含 7 行为（含 DpHold / Berth / MrcAnchor / MrcHeaveTo）。D3.1 按架构 §8.3 核心 5 行为 + MRC_Drift 出发，DP_Hold / Approach 等港内操作行为留给 DEMO-3（8/31）根据 ODD-C 需求扩展。`BehaviorPlan.msg` 枚举保留 0-6 全量占位，D3.1 仅激活 0-4。

### 4.2 行为激活条件

#### 4.2.1 Transit（航路跟随）

```
active = (ODD_State.current_zone ∈ {A, B, C})
       ∧ (MissionGoal.received)
       ∧ (¬COLREG_AVOID.active ∨ COLREG_AVOID not in active_set)
       ∧ (HealthState ≠ CRITICAL)
```

**IvP 效用函数**（D3.1 stub 为分段常数兜底，完整版 D3.1 E2）：

```
Utility_Transit(ψ, u) =
  w_heading × max(0, 1 − |ψ_desired − ψ| / 90°)   // 航向偏差惩罚，90° 外为 0
  + w_speed × u / u_max                              // 鼓励在限速内保持高速
```

`[TBD-HAZID]`: w_heading=0.5, w_speed=0.5（默认等权）

#### 4.2.2 COLREGs Avoidance（COLREGs 避碰）

```
active = (M6.COLREGs_ConstraintMsg.received within 2s)
       ∧ (M6.conflict_detected == true)
       ∧ (ODD_State.current_zone ≠ C)          // 港内不适用
       ∧ (HealthState ≠ CRITICAL)
```

**IvP 效用函数**（D3.1 stub）：

```
Utility_ColregAvoid(ψ, u) =
  1.0  if ψ ∈ M6.allowed_direction_range     // 完全符合 M6 指令
  0.0  otherwise                               // 违反 COLREGs 约束
```

完整版增加 CPA 改善奖励和 TCPA 紧急度加权。

#### 4.2.3 Restricted Visibility（能见度不良）

```
active = (ODD_State.current_zone == D)       // ODD-D：能见度 < 2 nm
       ∧ (WorldState.visibility_nm < 2.0)
       ∧ (u_current > 0)
```

**IvP 效用函数**（D3.1 stub）：

```
Utility_RestrictedVis(ψ, u) =
  w_slow × max(0, 1 − u / safe_speed)         // Rule 19：安全速度，禁止高速
  + w_cpa × bonus_cpa(ψ)                        // 加大 CPA 边距
```

`[TBD-HAZID]`: w_slow=0.7, w_cpa=0.3, safe_speed=8.0 kn

#### 4.2.4 Channel Following（狭水道跟随）

```
active = (ODD_State.current_zone == B)       // ODD-B：狭水道
       ∧ (WorldState.in_vts_zone == true)     // 进入 VTS 区
       ∧ (¬MRC_DRIFT.active)
```

**IvP 效用函数**（D3.1 stub）：

```
Utility_ChannelFollow(ψ, u) =
  1.0  if ψ ∈ channel_centerline ± 30°       // Rule 9：靠右航行
  0.3  if ψ ∈ channel_centerline ± 60°        // 允许小幅偏离
  0.0  otherwise
```

`[TBD-HAZID]`: channel_centerline 从 WorldState.enc_data 提取

#### 4.2.5 MRC Drift（应急漂航）

```
active = (M1.mode_cmd == MRC_TRIGGERED)
       ∨ (HealthState == CRITICAL)
       ∨ (all_inputs_timeout > 5s)
```

**IvP 效用函数**：MRC_Drift 不产生 IvP 效用函数——**直接冻结 IvP 输出，强制 primary=MRC_DRIFT**。

输出：`heading_range=[0,360)`, `speed_range=[0,0]`（推进器停车），`confidence=1.0`。

### 4.3 权重集切换矩阵

| HealthState | COLREG_AVOID 乘数 | TRANSIT 乘数 | 其他行为乘数 | CPA_safe 乘数 |
|---|---|---|---|---|
| NORMAL | 1.0× | 1.0× | 1.0× | 1.0× |
| DEGRADED（输入超时 2-5s） | 1.3× | 0.8× | 1.0× | 1.2× |
| CRITICAL（全部超时 >5s 或 ODD=CRITICAL） | — | — | — | 强制 MRC_DRIFT |

### 4.4 MRC_Drift 始终最高优先级实现

MRC_Drift 不通过 IvP 权重而是通过**后处理覆盖**实现：

```cpp
// Step 7: BehaviorPriority（在 IvP 求解之后）
if (active_set contains MRC_DRIFT) {
  result.primary    = MRC_DRIFT;
  result.heading    = [0, 360);
  result.speed      = [0, 0];        // 推进器停车
  result.confidence = 1.0;
  result.rationale  = "MRC_DRIFT override: " + trigger_reason;
  // 不发布 ivp_contributions（MRC 下不适用）
  return result;  // 跳过正常仲裁路径
}
```

**与架构 §8.3 一致**：MRC_Drift weight=1.0（始终最高），适用 ODD=任何。

## 5. IvP 求解器规范

### 5.1 实现路径

| 决策 | 依据 |
|---|---|
| **自实现 C++**（方案 B） | RFC-009 法务-hat + M4-hat 签字（2026-05-08）：零 license 风险，CCS 审计最干净 |
| **禁止引用 libIvP 代码** | 法务-hat 附加条件 (1)：独立实现算法思想，保留注释声明独立开发 |
| **复用 salvage 代码** | `.salvage-d3.1/` 中 `ivp_solver.cpp`(145 LOC) + `ivp_function.hpp`(167 LOC) + `ivp_combine.hpp`(48 LOC) + `ivp_domain.hpp`(70 LOC) 作为起点 |

### 5.2 离散化分辨率

| 维度 | 分辨率 | 步数 | 可配置 | 来源 |
|---|---|---|---|---|
| **航向 ψ** | **1.0°** | 360 | `m4.arbitration.heading_domain_resolution_deg` (YAML) | `m4_params.yaml` |
| **速度 u** | **0.5 kn** | ~44（0-22 kn） | `m4.arbitration.speed_domain_resolution_kn` (YAML) | `m4_params.yaml` |
| 速度域范围 | [0, 22 kn] | — | `speed_domain_min_kn` / `speed_domain_max_kn` | `m4_params.yaml` |

**设计理由**：
- **航向 1°**：前端 IvpRiskGradientLayer 箭头渲染精度需求 ≥5°，1° 提供 5× 过采样余量；网格 360 点 × 44 点 = 15,840 单元，i7 上 ~15ms（满足 250ms 周期约束）
- **速度 0.5 kn**：典型船舶速度变化粒度（CCS 规范中速度控制精度要求 ≤1 kn）；0.5 kn 提供 2× 精度余量
- 两个分辨率均可通过 YAML 运行时配置，允许 HAZID 后针对实船性能精调

### 5.3 IvP 算法（两遍网格搜索）

```
Algorithm: IvP_TwoPass_GridSearch
─────────────────────────────────

Input:
  active_fns[]   : list of WeightedFunction {weight, IvPFunction}
  constraints    : IvPHardConstraints
  domain         : IvPHeadingDomain × IvPSpeedDomain

Output:
  IvPSolution    : {heading_min, heading_max, speed_min, speed_max, optimality_margin, rationale}
  or nullopt     : on empty active set, infeasible bounds, timeout, no feasible cell

Constants:
  kTopFeasibleFraction = 0.9   // fraction of best utility defining interval boundary
  kTimeoutMs           = 50    // max solve wall-clock time (YAML: m4.arbitration.ivp_timeout_ms)

─────────────────────────────────

1. SOLVE(active_fns, constraints):
   if active_fns.empty():           return nullopt  // nothing to optimize
   if speed_min > speed_max:        return nullopt  // infeasible speed range

   t_start = now()
   (best_utility, cells_eval, cells_feasible) = FIND_BEST(active_fns, constraints, t_start)

   if best_utility < 0.0:           return nullopt  // timeout or no feasible cell
   if (now() - t_start) > timeout:  return nullopt  // timeout guard

   return COLLECT_INTERVAL(active_fns, constraints, best_utility)

2. FIND_BEST(active_fns, constraints, t_start) → double:
   best = -1.0
   for each ψ_i in heading_domain:
     if ψ_i not in allowed_ranges:   continue       // COLREGs heading constraint
     for each u_j in speed_domain:
       if u_j < speed_min or > speed_max: continue   // ODD speed constraint
       if now() - t_start > timeout:  return -1.0    // timeout (signal to caller)
       util = Σ_k (weight_k × f_k.evaluate(ψ_i, u_j))
       if util > best: best = util
   return best

3. COLLECT_INTERVAL(active_fns, constraints, best_utility) → IvPSolution:
   threshold = kTopFeasibleFraction × best_utility
   h_min, h_max = +∞, -∞
   u_min, u_max = +∞, -∞

   for each ψ_i, u_j in feasible grid:
     util = Σ_k (weight_k × f_k.evaluate(ψ_i, u_j))
     if util ≥ threshold:
       h_min = min(h_min, ψ_i); h_max = max(h_max, ψ_i)
       u_min = min(u_min, u_j); u_max = max(u_max, u_j)

   rationale = "IvP: best_util={best} cells_feasible={N}"
   return {h_min, h_max, u_min, u_max, best_utility, rationale}
```

**性能特征**：
- 网格规模：360 × 44 = 15,840 cells（@1°/0.5kn）；典型 2-5 激活行为
- 每 cell 计算：~5 × evaluate() ≈ 10 FLOPs → ~158k FLOPs per pass × 2 passes = ~316k FLOPs
- Benchmark：Intel i7 @ 2.6GHz → ~15-25ms（满足 50ms timeout）
- Jetson 边缘设备：估计 ~40-80ms → 需 YAML 调整分辨率或缩小域

### 5.4 M6 COLREGs 硬约束注入

M6 的 `COLREGs_ConstraintMsg` 包含字段：
- `constraints[]`：每约束含 `direction_enum` (PORT/STARBOARD/NONE) + `min_action_deg`
- `conflict_detected`：bool，冲突标志
- `active_rules[]`：活跃规则列表

#### 5.4.1 约束映射

| M6 输出 | IvPHardConstraints 映射 |
|---|---|
| `constraint.direction == STARBOARD` | `heading_allowed_ranges_deg` 添加 [current_ψ+min_action_deg, current_ψ+180°]（右舷半平面） |
| `constraint.direction == PORT` | `heading_allowed_ranges_deg` 添加 [current_ψ−180°, current_ψ−min_action_deg]（左舷半平面） |
| `constraint.direction == NONE` | 无 heading 约束 |
| `constraint.direction == SLOW_DOWN` | `speed_max_kn` 缩至 `constraint.max_speed_kn` |
| `conflict_detected == true` | 添加到 rationale；`confidence` 降低（0.95 → 0.70） |

#### 5.4.2 M6 硬约束清空可行集时的 Fallback

**场景**：M6 约束过于严格（如双目标夹击导致所有航向被排除），或速度约束与 heading 约束合并后无可行 cell。

**Fallback 策略————保守应急行为**：

```
if IvPSolver::solve() returns nullopt:
  1. 记录 ASDR 事件: decision_type="ivp_infeasible", decision_json=active_rules + constraints
  2. 尝试逐步放松:
     a. 移除 CPA 约束（仅保留 heading + speed bounds）→ 重试 solve()
     b. 仍 infeasible → 移除 heading 约束（仅保留 speed bounds）→ 重试 solve()
     c. 仍 infeasible → 完整回退
  3. 完整回退：
     primary = MRC_DRIFT（若 active）否则 COLREG_AVOID
     heading_range = [current_ψ − 90°, current_ψ + 90°]   // 允许 ±90° 机动
     speed_range   = [0, 0.5 × u_current]                  // 大幅减速
     confidence    = 0.30                                  // 极低置信
     rationale     = "IvP infeasible fallback: " + constraint_summary
```

**设计理由**：比完全放弃控制更安全——至少保留"大幅减速 + 允许有限转向"的应急能力。M7（Checker）在 SIL 2 下对 M4 输出做二次校验，可 VETO 极端不安全输出。

#### 5.4.3 PATH-S 独立性保证

```
M4 与 M7 的隔离保证（满足 Doer-Checker 独立实现原则）：
  ✅ M4 不以任何方式 #include M7 内部头文件
  ✅ M4 不链接 M7 共享库（libm7_core）
  ✅ M4 不共享 M7 的数据结构/工具类
  ✅ CI 脚本 check-doer-checker-independence.sh 持续验证
  ✅ M4 仅通过 ROS2 topic（/l3/m4/behavior_plan）与 M7 通信
```

## 7. confidence 字段与 ASDR 规范

### 7.1 confidence 计算模型

`confidence ∈ [0, 1]` 是 M4 对仲裁结果可信度的自评估：

```
confidence = clamp(base_confidence × freshness_factor × ivp_quality_factor, 0.0, 1.0)

where:
  base_confidence:
    0.95  if IvP solved successfully
    0.75  if IvP solved with relaxed constraints
    0.60  if no active behavior (standby)
    0.30  if conservative fallback triggered

  freshness_factor:
    1.0   if all inputs ≤ 2s
    0.8   if 1 input stale (2-5s)
    0.5   if 2+ inputs stale

  ivp_quality_factor:
    min(1.0, optimality_margin / 0.5)   // margin ≥ 0.5 → full quality
                                         // margin < 0.5 → linear degradation
    (optimality_margin = best_utility − second_best_utility)
```

### 7.2 ASDR 事件类型（M4 发布到 `/l3/asdr/record`）

| 事件 | decision_type | 触发条件 | decision_json 内容 |
|---|---|---|---|
| 行为激活变化 | `behavior_switch` | primary 变化 | `{from, to, active_count, odd_zone}` |
| IvP 求解失败 | `ivp_infeasible` | solve() returns nullopt | `{active_rules, constraint_summary, fallback_used}` |
| ODD 跳变 | `odd_transition` | current_zone 变化 | `{from_zone, to_zone, active_behaviors_before, active_behaviors_after}` |
| 输入超时 | `input_timeout` | 任一消息源超时 | `{source_module, age_ms, health_state_before, health_state_after}` |
| 权重集切换 | `weight_set_switch` | NORMAL↔DEGRADED↔CRITICAL | `{from, to, trigger_reason}` |
| 行为计划 | `behavior_plan` | 每周期 4 Hz | `{primary, heading_range, speed_range, confidence, active_behaviors}` |

## 14. 设计决策记录（ADR）

### ADR-D3.1-001：航向离散化分辨率 = 1.0°

**决策**：航向网格分辨率 1.0°，360 步。

**理由**：
- 前端 IvpRiskGradientLayer 渲染精度需求 ≥5°（8 方向箭头各间隔 45°），1° 提供 5× 余量
- 360 点 × 44 速度级别 = 15,840 cells，i7 上 ~15ms（满足 250ms 周期）
- 可通过 YAML 运行时调整（HAZID 后实船精调）

**备选方案**：5°（72 步）→ 网格太粗，区间边界误差 ±2.5°，M5 无法有效利用

---

### ADR-D3.1-002：MRC_Drift 采用后处理覆盖（非 IvP 权重 = 1.0）

**决策**：MRC_Drift 不通过 IvP 权重实现，而是**后处理覆盖**——任何 MRC_DRIFT 激活时直接跳过 IvP 求解，输出 heading=[0,360), speed=[0,0], confidence=1.0。

**理由**：
- MRC_Drift 不是"优化目标"而是"安全指令"——推进器停车不需要多目标权衡
- 架构 §8.3 规定 weight=1.0（始终最高），但 IvP 权重语义是"偏好强度"而非"绝对覆盖"
- 后处理覆盖确保 MRC 在任何情况下不可被其他行为的 utility 压倒

**备选方案**：IvP 中 weight=1.0 + MRC 效用函数全空间 = 1.0 → 相同效果但语义不清

---

### ADR-D3.1-003：M6 硬约束不可行时采用级联放松 fallback

**决策**：当 M6 COLREGs 约束导致 IvP 可行集为空时，按 CPA→heading→speed 顺序级联放松，最终回退到"±90° 转向 + 50% 减速"的保守应急行为。

**理由**：
- 级联放松比一次性全量放弃更安全——逐步降低约束严格性
- CPA 首先放松（最宽松约束），heading 次之（COLREGs 核心），speed 最后
- 最终兜底"大幅减速 + 有限转向"比完全放弃控制更安全
- M7 Checker（SIL 2）对最终输出做二次校验 → 双重保护

---

### ADR-D3.1-004：ivp_contributions[] 采样 8 个固定罗盘方向

**决策**：ivp_contributions 发布 8 个固定的 45° 间隔方向（N/NE/E/SE/S/SW/W/NW），而非动态方向集。

**理由**：
- 前端 IvpRiskGradientLayer 渲染的视觉粒度需求是 8 方向箭头——固定方向集足够
- 固定采样简化计算：仅需 8 次 evaluate() 调用（每行为在每个方向上求 utility 最大值），而非完整网格搜索
- 每个采样方向的 speed 选取该方向上 utility 最大的速度值（单维 argmax over u）

**备选方案**：全网格采样（360×44 cells 的 utility 值全量广播）→ 带宽浪费（~500KB/msg），前端无法直接消费原始网格
