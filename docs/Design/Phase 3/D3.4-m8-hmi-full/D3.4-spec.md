## §3 ToR 自适应矩阵

### 3.1 主状态机（6 态，扩展现有 4 态）

```
                     ┌──────────────────────────────────────────────┐
                     │                                              │
     ┌───(TDL压缩 ∨ 人工请求)──→ REQUESTED ──(已知悉 click)──→ ACKNOWLEDGED
     │                               │                                │
     │                               ├──(超时)──→ TIMEOUT_MRC        │
    IDLE ←──(接管完成)───────────────┤                                │
     ↑                               ├──(URGENT条件)──→ URGENT_TOR ──┤
     │                               │    ├──(超时)──→ TIMEOUT_MRC   │
     │                               │    └──(已知悉)──→ ACKNOWLEDGED│
     │                               │                                │
     └──(ODD EDGE/OUT 硬重置)────────┘                                │
     └──(MRC执行完)──────────────────┘                                │
     └──(ACK超时/取消)────────────────────────────────────────────────┘
```

### 3.2 子状态：OperatorContext

来源：D2.1 M1 ODDState 新增字段 `operator_availability`（uint8 枚举）。

| OperatorContext | deadline_s | 场景 | 法律依据 |
|---|---|---|---|
| `ROC_OPERATOR` (0) | **60s** | ROC 工作站值守 | Veitch 2024 [R4] |
| `BRIDGE` (1) | **30s** | 驾驶台现场 | 情境保持最高 |
| `MESS` (2) | **90s** | 餐厅/休息室 | 需移动至驾驶台 |
| `CABIN` (3) | **120s** | 卧舱 | 唤醒+移动+情境重建 |

### 3.3 计时器策略（方案 B）

```
进入 REQUESTED:
  deadline_s = lookup(OperatorContext)
  elapsed = 0
  display_text = "ToR 接管请求 · {deadline_s}s 窗口"

OperatorContext 降级 (CABIN→MESS→BRIDGE→ROC):
  if elapsed < 5s:
    deadline_s = lookup(新OperatorContext)   # 奖励：新状态窗口
    elapsed = 0
  else:
    deadline_s = max(lookup(新), elapsed)    # 不惩罚已等待

OperatorContext 升级 (BRIDGE→MESS):
  无操作；剩余时间不变

ODD 子域切换:
  EDGE/OUT → NOMINAL:  硬重置 (elapsed=0, deadline_s=lookup)
  NOMINAL 内子域切换:   继承剩余时间
```

### 3.4 URGENT_TOR 子分支

```
触发条件 (任一):
  - M7 Checker 心跳丢失 > 500ms (M8 watchdog)
  - Y-axis Reflex Arc 激活 (§10)
  - M1 ODD EDGE/OUT 进入
  - BNWAS 等效告警 (§11)

URGENT 模式行为:
  - deadline_s = min(当前剩余, 30s)
  - 倒计时红色闪烁 (--c-danger, 1Hz pulse, CSS @warn-flash)
  - "已知悉"按钮旁路 ≥5s 强制等待
  - M8 多通道蜂鸣告警
  - 备份通道同步激活 (§3.7)
```

### 6.2 M8 Watchdog 逻辑

```
class M7CheckerWatchdog {
  timeout_warn_ms = 100       // 丢帧 > 100ms → UI 琥珀告警
  timeout_escalation_ms = 500 // 丢帧 > 500ms → 触发 URGENT_TOR

  on_missed_heartbeat():
    if elapsed > 100ms:  set display_state.m7_checker_alive = false
    if elapsed > 500ms:  trigger_urgent_tor("m7_checker_heartbeat_lost")
  
  on_heartbeat_recovered():
    set display_state.m7_checker_alive = true
    log_asdr_event("m7_checker_recovered", elapsed)
}
```

## §7 active_role 对称双角色

### 7.1 三向枚举

```idl
uint8 active_role  # 0=PRIMARY_ON_BOARD  船上船长为主
                   # 1=PRIMARY_ROC       ROC 操作员为主
                   # 2=DUAL_OBSERVATION  双端观察（无主动控制）
```

### 7.2 双确认协议

```
角色切换流程:
  1. 请求端: POST /tor/role_switch { target_role: PRIMARY_ROC }
  2. 对方端: UI 弹出确认 Modal "ROC 请求控制权 · [接受] / [拒绝]"
  3. 对方端接受:
     - 旧 PRIMARY → DUAL_OBSERVATION
     - 新 PRIMARY → PRIMARY_ROC
     - M8 记录 ASDR: role_switch 事件 (含双方操作员 ID + 时间戳)
  4. 对方端拒绝 / 超时 30s: 角色不变, M8 记录拒绝事件
```

### 7.3 角色轴视图差异

| 信息层 | PRIMARY_ON_BOARD（船长） | PRIMARY_ROC（操作员） | DUAL_OBSERVATION |
|---|---|---|---|
| SAT-1 | 简化，直觉式可视化 | 完整，数字量化 | 完整（可折叠） |
| SAT-2 | 高层摘要 | 完整规则链 | 按需展开 |
| SAT-3 | 关键时间节点 | 完整不确定性分布 | 摘要 + 可选展开 |
| ToR 界面 | 一键接管 | 详细+分步确认 | 仅观察，无控制 |
| ToR 倒计时 | 驾驶台本屏 | ROC 主屏 | 辅助屏 |
| M7 badge | 大号（驾驶台可视距离） | 标准 | 最小 |

### 12.1 架构

### 12.2 M8 责任

```
M8 按帧记录:
  - 每 50Hz 产出 1 条 replay record (JSON 到磁盘)
  - 格式: { seq, timestamp, display_state, own_ship, targets[], sat2, sat3, sotif }
  - 存储: /runs/{run_id}/replay/{seq:06d}.json

接口 (M8 Python FastAPI):
  GET /api/v1/runs/{run_id}/replay?seq={N}  → 返回第 N 帧 JSON
  GET /api/v1/runs/{run_id}/replay/range?from={A}&to={B} → 帧范围
```

### 12.3 Puppeteer Worker（独立组件，非 M8 代码）

```
独立 Dockerfile (tools/docker/Dockerfile.puppeteer-worker):
  - puppeteer (Chromium)
  - @ffmpeg/ffmpeg (GIF 编码)
  
关键帧选择逻辑:
  1. 读 Arrow log → 找 event_type 变化点
  2. 以变化点为中心, ±10s 取 replay frames
  3. 拼接为 timeline.gif (12fps, 480px宽)
  4. 在 event 时刻截图 12 个关键帧
```
