### 3.2 Checkpoint Gate 规格

每个 Checkpoint Gate 在进入下一段前自动执行以下检查，任一失败则暂停并告警（不自动终止，由值守工程师决定继续或标记 P1 后继续）：

| 检查项 | 通过条件 | 失败处理 |
|---|---|---|
| P0 崩溃计数 | = 0 | 立即终止整段，标记 P0，8h 测试失败 |
| M7 PATH-S violation | = 0 | 标记 P0，终止 |
| `/m7/sil_observability` 心跳 | 最近 5s 内有消息 | 标记 P0，终止 |
| 该段延迟 p99 | AvoidancePlan ≤ 1000ms；ReactiveOverride ≤ 200ms | 标记 P1，可继续 |
| 该段 ASDR SHA-256 | 全 PASS | 任一失败标记 P0，终止 |

Checkpoint Gate 产出：`evidence/seg{N}/checkpoint_{A|B}.json`（含所有检查项结果 + 时间戳）。

### 3.3 实时监控仪表盘

`dashboard_server.py` 提供 `http://localhost:8888`，WebSocket 每 5s 推送一次状态，展示以下面板：

| 面板 | 内容 | 数据源 |
|---|---|---|
| **P0 告警灯** | 6 条 P0 条件实时状态（绿/红）| m7_obs_watchdog + pgrep + asdr_verifier |
| **场景进度** | 当前段 / 总进度条（已完成 N/50）+ 当前运行场景名 | run_8h_integration 状态文件 |
| **延迟曲线** | 关键 4 条 topic 的 p95 滚动折线图（最近 30min）| latency_8h.csv rolling window |
| **ASDR 完整性** | 累计校验数 / PASS / FAIL 计数 | asdr_integrity.csv |
| **模块心跳** | M1–M8 各节点存活状态（8 个 LED）| pgrep 每 10s 刷新 |
| **Checkpoint 状态** | CP-A / CP-B 通过时间戳或 ⏳ 等待中 | checkpoint JSON |

仪表盘截图存档：Checkpoint 通过时自动截图保存到 `evidence/dashboard_snapshots/cp_{A|B}.png`；8h 结束时截最终状态图 `evidence/dashboard_snapshots/final.png`。

## 4. 50 个 High-Stakes 场景选取

### 4.1 选取原则（后验选取）

D3.6 执行完毕后（约 8/10），从其 `evidence/cube_results.csv` + `evidence/sotif_coverage_d3.6.html` + `evidence/gifs/` 按以下三维综合评分排序，取 top-50：

```
场景风险分 = w₁ × (1 - D3.6归一化总分)   # 得分越低越高风险
           + w₂ × FAIL_count             # D3.6中失败次数
           + w₃ × SOTIF命中次数           # SOTIF假设违反触发次数
           w₁ = 0.4, w₂ = 0.4, w₃ = 0.2
```

### 4.2 类型配额约束

top-50 中须满足以下最低类型配额（避免全部集中于单一风险类型）：

| 类型 | 最少数量 | 对应注入段 |
|---|---|---|
| MRC 触发类（M7 → MRC 执行链）| ≥ 12 | Seg-1 |
| Y-axis Reflex Arc 触发类（极近距离旁路）| ≥ 12 | Seg-2 |
| SOTIF 假设违反类（6 类中至少覆盖 4 类）| ≥ 15 | Seg-3 |
| 其他高风险（VETO 触发 / ODD 边界穿越）| ≥ 5 | 按类型分配到各段 |

配额不足时（例如某类型 D3.6 run 中未出现足够 FAIL），从该类型最低评分场景补足，并在报告中标注"按配额补充"。

### 4.3 场景文件组织

选取完成后将 50 个 YAML 拷贝到 `scenarios/high_stakes/`，目录结构：

```
scenarios/high_stakes/
  seg1_mrc/          # Seg-1 场景（按注入顺序命名 s01_*.yaml ... s15_*.yaml）
  seg2_reflex/       # Seg-2 场景
  seg3_sotif/        # Seg-3 场景
  manifest.csv       # 50 行，含场景名 / 类型 / D3.6风险分 / 注入段
```

## 6. §15.2 接口矩阵 24 行端到端延迟测量

### 6.1 测量工具：`latency_monitor.py`

实现方式：为 §15.2 接口矩阵的每对 send/receive topic 部署一个 Python ROS2 subscriber pair，订阅两端消息，用 `header.stamp` 差值计算 `t_receive - t_publish`（nanosecond 精度），每 60s 将当前窗口的 p50/p95/p99 追加写入 `evidence/latency_8h.csv`。

IEC 61508 合规设计：
- `latency_monitor.py` 作为**独立 ROS2 节点**，仅订阅（不发布任何决策 topic），不影响主决策链路时序
- 时钟同步要求：SIL 环境内所有 Docker 容器共享宿主机时钟（OrbStack 默认行为），宿主机须启用 chrony/PTP 同步（≤ 1ms 精度）

## 8. `/m7/sil_observability` 只读 Topic（G P1-G-1 关闭）

### 8.1 背景

G P1-G-1（7 角度评审 finding）：M7 Safety Supervisor 的 verdict 当前经由 `/m7/safety_verdict` → M1 → M8 的路径到达 HMI，存在 verdict 影响 Doer 决策链路的风险。

### 8.2 修复设计

在 M7 Safety Supervisor 中新增一个**只读观测 topic**，直接发布 M7 内部状态摘要，绕过 Doer 决策链路，由 M8 直接订阅用于透明性显示：

```
IDL: l3_msgs/M7Observability
  builtin_interfaces/Time stamp
  uint8 verdict_code          # 0=NOMINAL, 1=DEGRADED, 2=VETO, 3=MRC
  string rationale            # 最近一次 verdict 原因（max 256 chars）
  float32[6] hc_scores        # 6 硬约束评分（0.0=OK, 1.0=VIOLATION）
  bool path_s_clean           # PATH-S CI 最近结果
  uint8 schema_version        # = 1

Topic: /m7/sil_observability
Publisher: M7 SafetySupervisor（独立 timer callback，10 Hz，不依赖 verdict 触发）
Subscriber: M8 HMI Bridge（只读，仅用于 SAT-1 透明性显示，不参与仲裁）
```

**独立性保证**：`/m7/sil_observability` 的 publisher 在 M7 内部使用独立的 timer callback（不共享 verdict publisher 的回调），确保即使 verdict 触发链路阻塞，观测 topic 仍正常发布。

### 8.3 验证方法

`m7_obs_watchdog.py`：独立 Python 脚本，订阅 `/m7/sil_observability`，检测连续 5s 内无消息则触发 P0 告警，同时将每条消息的时间戳写入 `evidence/m7_obs_log.csv`。

G P1-G-1 关闭证据：`evidence/m7_obs_log.csv` + `evidence/latency_8h.csv` 中第 17 行（M7→M8 `/m7/sil_observability` p99 ≤ 50ms）共同证明。

## 9. ASDR 跨站点一致性验证

### 9.1 Proto 扩展（D3.7 新增字段）

当前 `idl/sil/asdr_event.proto` 无完整性字段。D3.7 在 proto 中新增一个字段：

```protobuf
message ASDREvent {
  // ... 现有字段 1–6 不变 ...
  bytes hmac_sha256 = 7;   // D3.7 新增：M7 写端计算，key=SIL_INTEGRITY_KEY env var
}
```

M7 ASDR 写端在生成每条记录时，对 `stamp + decision_id + payload_json` 三字段拼接后计算 HMAC-SHA256，写入 `hmac_sha256` 字段。`SIL_INTEGRITY_KEY` 通过 Docker Compose env 注入（SIL 内部密钥，不涉及跨网络传输）。

### 9.2 验证方案

`asdr_sha256_verifier.py` 在 8h 运行期间实时追加验证每条 ASDR 记录：

```python
# 伪代码逻辑
key = os.environ["SIL_INTEGRITY_KEY"].encode()
for asdr_record in subscribe("/asdr/decision_log"):
    payload = (asdr_record.stamp.SerializeToString()
               + asdr_record.decision_id.encode()
               + asdr_record.payload_json.encode())
    expected_hmac = hmac.new(key, payload, sha256).digest()
    computed_hmac = asdr_record.hmac_sha256
    status = "PASS" if hmac.compare_digest(computed_hmac, expected_hmac) else "FAIL"
    append_csv("evidence/asdr_integrity.csv",
               [asdr_record.stamp, asdr_record.decision_id,
                computed_hmac.hex(), status])
    if status == "FAIL":
        trigger_p0_alert("ASDR_INTEGRITY_FAILURE")
```

### 9.2 输出格式

`evidence/asdr_integrity.csv` 列：`timestamp, scenario_id, segment, computed_sha256, expected_sha256, status`

汇总统计写入 `D3.7-integration-report.md`：总记录数 / PASS 数 / FAIL 数（DEMO-3 准入要求：FAIL = 0）。

## 10. P0 崩溃判定标准

以下任一事件发生，立即触发 P0 告警，当前段标记失败，8h 测试总体 P0 崩溃计数 +1：

| ID | 事件描述 | 判定依据 | 自动检测 |
|---|---|---|---|
| P0-1 | 任意 M1–M8 节点进程崩溃（SIGABRT / SIGSEGV / OOM）| `pgrep` 存活检查每 10s 一次，失败即告警 | `run_8h_integration.py` 内置 watchdog |
| P0-2 | M7 VETO 后 Doer 继续输出决策指令（Doer-Checker 失效）| `/m7/safety_verdict.verdict=VETO` 后 5s 内 `/l3/m5/avoidance_plan` 仍有新消息 | `m7_obs_watchdog.py` |
| P0-3 | MRC 触发后 TMR > 60s 未进入安全等待状态 | ASDR `mrc_trigger_stamp` → `safe_state_stamp` 差值 | `asdr_sha256_verifier.py` 附带计算 |
| P0-4 | Y-axis Reflex Arc 触发后 > 500ms `/reflex/override_cmd` 未到达 L5 stub | `/reflex/override_cmd` 时间戳 vs Reflex 触发事件时间戳 | `latency_monitor.py` 事件检测 |
| P0-5 | `/m7/sil_observability` topic 连续 > 5s 无消息 | `m7_obs_watchdog.py` 心跳检测 | `m7_obs_watchdog.py` |
| P0-6 | 任意 ASDR 记录 SHA-256 校验失败 | `asdr_sha256_verifier.py` 返回 FAIL | `asdr_sha256_verifier.py` |

**不属于 P0（属于 P1/P2，记录不终止）**：
- 单个场景评分 FAIL（功能缺陷，非安全崩溃）
- 延迟超阈值但未导致决策错误（记录，DEMO-3 展示时说明改进路径）
- M5 IPOPT fallback 触发 NomotoFallback（已有兜底，不算崩溃）
- 单个场景仿真器内部 timeout（重试一次后记录 P1）
