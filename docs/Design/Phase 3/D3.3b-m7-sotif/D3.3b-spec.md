## 3. 架构上下文

### 3.1 ISO 21448 §6 SOTIF Area 完整性映射（关闭 C P1-C-2）

ISO 21448 §6 定义三个 SOTIF area：
- **Area 1（Known Safe）**：已知安全场景 — 系统正确识别和响应
- **Area 2（Known Unsafe）**：已知不安全场景 — 系统能检测但无法应对
- **Area 3（Unknown Unsafe）**：未知不安全场景 — 系统既不能检测也不能应对（SOTIF 的核心关注区域）

C P1-C-2 要求为每类假设明确映射到 SOTIF area 并提供证据来源链。

| 假设 # | 假设名称 | SOTIF Area | 触发条件证据来源 | 该 area 的典型触发场景 | 监控指标 | 退化至 Area 2/3 的条件 |
|---|---|---|---|---|---|---|
| ① | AIS/雷达一致性 | **Area 2 → Area 3** | M2 WorldState.confidence 字段 | 目标船 AIS 关闭/故障；雷达目标与 AIS track 关联失败 | 融合置信度 < 0.5 | 置信度持续 < 0.5 超过 30s → Area 3（传感器信息不可信） |
| ② | 目标运动可预测性 | **Area 2 → Area 3** | M2 WorldState.confidence 代理（当前）；M2 预测 RMSE 字段（DEMO-3）| 目标船机动不可预测（如紧急转向）；模型漂移 | 预测 RMSE > 50m/30s | 预测误差持续超标 → Area 3（运动假设失效） |
| ③ | 感知覆盖充分性 | **Area 2 → Area 3** | M2 WorldState.targets[].classification（当前代理）；M2 盲区占比字段（DEMO-3）| 密集交通遮挡；传感器 FOV 外目标 | 盲区占比 > 20% | 盲区扩大趋势 → Area 3（碰撞威胁不可见） |
| ④ | COLREGs 可解析性 | **Area 2 → Area 3** | M6 COLREGsConstraint.confidence 字段 | 多船同时冲突超 M6 推理能力；非标准会遇几何 | 连续失败 ≥ 3 次 | 连续失败 → Area 3（避碰规则推理失效） |
| ⑤ | 通信链路可用性 | **Area 2** | 通信链路 RTT/丢包率监控 | 卫星通信中断；近岸网络拥塞 | RTT > 2s 或丢包 > 20% | Area 2（已知不安全 — 可检测但不可恢复，触发 D2 降级） |
| ⑥ | L3 Checker 否决率 | **Area 2 → Area 3** | X-axis CheckerVetoNotification 事件流（RFC-003） | 连续轨迹输出被 X-axis 否决；Doer-Checker 分歧激增 | 否决率 > 20%/100 周期 | 高否决率 → Area 3（Doer 输出系统性不可信） |

> **证据来源链**：每个假设的监控数据路径从 Doer 模块（M2/M5/M6）经 l3_msgs IDL → M7 独立验证（不依赖 Doer 推理）→ 当 Doer 状态 = DEGRADED/FAILED 时，M7 SOTIF 自动降级到保守阈值（遵循决策四 §2.5 独立性约束，§11.3 第二段）。

### 3.2 6 类假设违反检测矩阵（统一为 6，关闭 C P1-C-1）

| # | AssumptionId (enum) | 监控指标 | 当前代码实现 | 违反阈值 | 滑窗需求 | 响应 | HAZID 标注 |
|---|---|---|---|---|---|---|---|
| ① | `kAisRadarConsistency` (0) | 融合置信度 | `check_ais_radar()` — 时间追踪 + 时长比较 | < 0.5 持续 > 30s | ❌ 简单时间追踪 | 目标置信度下调；M7 PERF 保守 CPA 告警 | [TBD-HAZID-SOTIF-001] |
| ② | `kMotionPredictability` (1) | 目标运动预测 RMSE | `check_motion_predictability()` — world.confidence < 0.4 代理 | > 50m/30s | ❌ 当前时间追踪（待 M2 RMSE 字段后升级滑窗） | 加大 CPA 安全边距 × 1.3 | [TBD-HAZID-SOTIF-002] |
| ③ | `kPerceptionCoverage` (2) | 感知盲区占比 | `check_perception_coverage()` — unknown target 占比代理 | > 20%（of 360°） | ❌ 无状态（每周期独立判断） | 降低 D3/D4 允许等级 | [TBD-HAZID-SOTIF-003] |
| ④ | `kColregsSolvability` (3) | COLREGs 解析失败 | `check_colregs_solvability()` — 连续失败计数器 | ≥ 3 次连续 | ❌ 连续计数器（非滑窗） | 触发减速 + ROC 告警；如持续 > 30s → MRM-02 | [TBD-HAZID-SOTIF-004] |

### 3.3 Doer-Checker 独立性约束（与 D3.3a 共享原则）

M7-sotif 与 M7-core 同为 M7 包的独立实现路径，共同遵循决策四独立性约束：

- **代码独立性**：M7-sotif 不复用 M1–M6 任何源文件/header；仅 `#include l3_msgs/msg/*.hpp` + `l3_external_msgs/msg/CheckerVetoNotification.hpp`
- **数据结构独立性**：不引用 `mass_l3::m1::*` 等 Doer 命名空间
- **库白名单**：rclcpp / l3_msgs / l3_external_msgs / Eigen 5.0.0 / spdlog 1.17.0（仅日志）/ yaml-cpp 0.8.0（仅 YAML 注入）
- **库黑名单**（CI 阻断）：CasADi / IPOPT / GeographicLib / nlohmann::json / Boost.*
- **运行时独立性**：独立 OS 进程（M7 整体；M7-sotif 与 M7-core 可在同进程但不同编译单元）

### 3.4 RFC-003 Alignment（enum-only veto + 100 周期 = 15s 滑窗）

| RFC-003 决议 | Spec 落地 |
|---|---|
| M7 仅按 VetoReasonClass enum 分类计数，**不解析 veto_reason_detail** | §4.2：M7-sotif 订阅 `/checker/veto_notification`，读取 `veto_reason_class` 字段分类计数；`veto_reason_detail` 仅透传至 ASDR |
| 100 周期 = 15s 滑窗（RFC-003 锁定，不可变） | §5.1：专用 `SlidingWindow15s` 循环缓冲区，编译期 `constexpr size = 100` |
| Checker 否决率 > 20% → 升级 SOTIF 告警（[HAZID 校准]） | §3.2 假设⑥：`kCheckerVetoRateThreshold = 0.20`（YAML 可注入，RFC-003 锁定默认值） |
| M7 监控 L3 Checker 否决率仅 | §1.3：仅监控 L3 层否决；L2/L4/L5 层由系统层 ASDR 聚合 |

## 4. 接口契约

### 4.1 `l3_msgs/SotifMetrics` IDL

位置：`src/l3_tdl_kernel/l3_msgs/msg/SotifMetrics.msg`（新文件）

遵循 l3_msgs 消息规范（`uint16 schema_version` + `builtin_interfaces/Time stamp` 首字段节）和枚举模式（`uint8` 行内常量定义）。采用通用数组结构，6 条元素一一对应 `AssumptionId` 枚举的前 6 个值。

```
# M7 SOTIF assumption violation metrics (topic: /sil/sotif_metrics @10Hz)
# Per v1.1.3 §11.3 + RFC-003 + D3.3b-spec §4.1

uint16 schema_version  # 113 = v1.1.3
builtin_interfaces/Time stamp

# Enumerated assumption IDs — MUST match AssumptionId enum order in assumption_monitor.hpp
uint8 ASSUMPTION_AIS_RADAR_CONSISTENCY    = 0  # ① AIS/Radar fusion confidence
uint8 ASSUMPTION_MOTION_PREDICTABILITY    = 1  # ② Target motion prediction RMSE
uint8 ASSUMPTION_PERCEPTION_COVERAGE      = 2  # ③ Perception blind zone fraction
uint8 ASSUMPTION_COLREGS_SOLVABILITY      = 3  # ④ COLREGs consecutive failures
uint8 ASSUMPTION_COMM_LINK                = 4  # ⑤ Communication RTT / packet loss
uint8 ASSUMPTION_CHECKER_VETO_RATE        = 5  # ⑥ X-axis Checker veto rate (RFC-003)

# Metric entry — one per assumption, 6-element fixed array
SotifMetricEntry[6] metrics

================================================================================
# Sub-message: SotifMetricEntry (nested — ROS2 .msg supports top-level struct path)
================================================================================

uint8 assumption_id       # ASSUMPTION_* enum value (0–5)
float32 violation_score   # Normalized metric (0.0–1.0, higher = worse)
                          #   ①: 1.0 − confidence (e.g., conf=0.3 → score=0.7)
                          #   ②: RMSE / 50m capped at 1.0
                          #   ③: blind_zone_fraction (direct 0.0–1.0)
                          #   ④: consecutive_failures / 3 capped at 1.0
                          #   ⑤: max(rtt/2s, packet_loss/20%) capped at 1.0
                          #   ⑥: veto_rate (direct 0.0–1.0)
uint16 window_count       # Number of violation samples in current sliding window (0–100)
                          #   For assumptions without sliding window: 0 (reserved, DEMO-3 fills)
bool is_violated          # Threshold exceeded this cycle
float32 raw_value         # Raw sensor value for ASDR transparency (un-normalized)
                          #   ①: confidence ∈ [0,1]
                          #   ②: RMSE in meters (proxy: world.confidence when RMSE unavailable)
                          #   ③: blind_zone_fraction ∈ [0,1]
                          #   ④: consecutive_failures ∈ [0,∞)
                          #   ⑤: RTT in seconds
                          #   ⑥: veto_rate ∈ [0,1]
================================================================================
```

**字段设计说明**：

- `assumption_id`：使用行内定义的 `ASSUMPTION_*` 枚举值（0–5），与 `AssumptionId` 枚举严格对齐。前端通过 `assumption_id` 路由到 `SotifMonitorStrip` 的对应显示行。
- `violation_score`：0.0–1.0 归一化得分，1.0 = 最严重违反。前缀端仪表盘实时颜色映射（绿/黄/红阈值）。
- `window_count`：滑窗内违反样本数（0–100）。假设⑥强制填充；假设①—⑤ DEMO-2 填 0，DEMO-3 依次升级各自的滑窗。
- `is_violated`：本周期是否触发违反阈值。`evaluate()` 返回的 `AssumptionStatus.violation_active[]` 直接映射。
- `raw_value`：原始传感器值（未归一化），用于 ASDR 日志透明度。

### 4.2 Topic 拓扑

```
M7-sotif 订阅:
  /l3/m2/world_state           l3_msgs/WorldState           @4Hz    → 假设①②③
  /l3/m6/colregs_constraint    l3_msgs/COLREGsConstraint    @2Hz    → 假设④
  /checker/veto_notification   l3_external_msgs/CheckerVetoNotification  事件 → 假设⑥

M7-sotif 发布:
  /sil/sotif_metrics           l3_msgs/SotifMetrics          @10Hz   → M8 桥接 → 前端 SotifMonitorStrip

M7-sotif 内部接口（不发布 topic）:
  CommLinkState                M7 内部结构体（通信 RTT/丢包率由 M7-core 的通信监控线程注入）→ 假设⑤
```

**CheckerVetoNotification 处理流程**（RFC-003 enum-only）：
1. 接收 `/checker/veto_notification`（事件）
2. 读取 `veto_reason_class` 字段（`uint8`，0–5）
3. 计数器 `++veto_count[reason_class]`
4. **不读取** `veto_reason_detail`（保持 Doer-Checker 独立性 — M7 不重新推理 X-axis 规则违反）
5. 每周期计算 `current_veto_rate = total_veto_count / window_size`（100 周期滑窗内）

### 4.3 DEMO-2 P1 Stub 定义（7/31 前）

metrics[i].assumption_id    = i (0–5)           # 枚举值
metrics[i].violation_score  = 0.0               # 全零 stub
metrics[i].window_count     = 0                 # 全零 stub
metrics[i].is_violated      = false             # 全 false stub

### 4.4 DEMO-3 完整路径（8/31 前）

真实值填充规则：

| 假设 | violation_score 计算 | window_count 来源 | raw_value 来源 |
|---|---|---|---|
| ① | `1.0 − world.confidence`（capped at 1.0） | 0（暂时；`ais_radar_low_since_` 已提供持续时间，但不记录样本计数） | `world.confidence` |
| ② | `min(1.0, (1.0 − world.confidence) / 0.4)`（代理数学，待 M2 RMSE） | 0（同①） | `world.confidence`（原始代理值） |

| ④ | `min(1.0, colregs_failure_count_ / 3.0)` | 0（连续计数器，非滑窗） | `colregs_failure_count_` |

| ⑥ | `veto_rate`（直接 0.0–1.0） | **真实值**：滑窗内否决事件计数（0–100） | `veto_rate` |

## 5. 滑动窗口设计

### 5.1 策略：独立缓冲区（方案 A — 已确认）

- **假设⑥**（CheckerVetoRate）：**强制 100 周期循环缓冲区**。`constexpr std::size_t kWindowSize = 100`（`safety_constants.hpp` RFC-003 锁定）。每个周期 push 本周期否决事件数（0 或 1），pop 最旧样本。当前 `veto_rate = sum(window) / kWindowSize`。
- **假设①②**：保持现有时间追踪逻辑（`ais_radar_low_since_` / `motion_low_since_` + 时长比较）。不引入滑窗 buffer。
- **假设③⑤**：每周期独立判断（无状态），不引入滑窗 buffer。
- **假设④**：保持现有连续失败计数器（非滑窗）。连续失败 → 递增；成功 → 清零。不引入滑窗 buffer。

**内存效率**：仅假设⑥需要 `std::array<uint8_t, 100>`（100 bytes）。总计滑窗内存开销 < 200 bytes（远低于 2.4KB 方案 B）。

### 5.2 SlidingWindow15s 接口设计

与现有 M7 类 `SlidingWindow15s`（M7 README 列出但未在 `assumption_monitor.cpp` 中使用）对齐：

```cpp
class SlidingWindow15s {
public:
  static constexpr std::size_t kCapacity = 100;  // RFC-003 LOCKED

  void push(bool veto_event) noexcept;            // Push this cycle's event
  [[nodiscard]] float veto_rate() const noexcept; // Current rate ∈ [0.0, 1.0]
  [[nodiscard]] std::uint16_t violation_count() const noexcept; // For window_count field
  void reset() noexcept;
private:
  std::array<bool, kCapacity> buffer_{};  // Stack-allocated (PATH-S — no malloc)
  std::size_t head_{0};
  std::size_t count_{0};
  std::uint16_t running_total_{0};
};
```

**周期驱动**：M7-sotif publisher 以 10Hz 定时器驱动（`rclcpp::TimerBase`）。每个周期：
1. 从 M7-core 的 shared state 获取最新 `WorldState` / `COLREGsConstraint` / `CommLinkState`
2. 从 CheckerVetoHandler 获取当前 `current_veto_rate`（由滑窗提供）
3. 调用 `AssumptionMonitor::evaluate()` 获得 `AssumptionStatus`
4. 组装 `SotifMetrics` 消息（6 × `SotifMetricEntry`）
5. 发布到 `/sil/sotif_metrics`

## 7. 状态机

```
     ┌──────────────────────────────────────────────┐
     │                                              │
     ▼                                              │
 ┌─────────┐  M1→M7: "M7_ACTIVATE"   ┌───────────┐ │
 │ INIT    │ ───────────────────────► │ MONITORING│ │
 └─────────┘                          └─────┬─────┘ │
     ▲                                      │       │
     │                            ┌─────────┼───────┘
     │                            │         │
     │              ┌─────────────┘         │
     │              ▼                       ▼
     │       ┌──────────┐           ┌───────────┐
     │       │ DEGRADED │           │ VIOLATED  │
     │       │   (1–2   │           │  (≥3      │
     │       │ 假设违反) │           │ 假设违反) │
     │       └────┬─────┘           └─────┬─────┘
     │            │                       │
     │       ┌────┴────┐            ┌─────┴──────┐
     │       ▼         ▼            ▼            ▼
     │  ┌────────┐ ┌──────┐  ┌──────────┐ ┌──────────┐
     │  │告警    │ │ToR   │  │MRC 触发  │ │MRM-01/02 │
     │  │SOTIF   │ │窗口  │  │(请求 M1  │ │(直接下发)│
     │  │升 级   │ │缩短  │  │  仲裁)   │ │          │
     │  └────────┘ └──────┘  └────┬─────┘ └─────┬────┘
     │            ▲         ▲     │             │
     │            │         │     ▼             ▼
     │            │         │  ┌─────────────────────┐
     │            │         │  │ M1 仲裁 → MRC 执行   │
     │            │         │  │ (MRM-01/02/03/04)   │
     │            │         │  └──────────┬──────────┘
     │            │         │             │
     │            │         │  ┌──────────▼──────────┐
     │            │         │  │ M7-sotif: reset()   │
     │            │         │  │ (清零所有状态)       │
     │            │         │  └──────────────────────┘
     │            │         │
     │            └─────────┴───── 假设违反解除 → 返回 MONITORING
     │
     └──── ODD 重新进入 / M7 CMD: "RESET" ────────────┘
```

**状态转换条件**：

| 转换 | 触发条件 | 动作 |
|---|---|---|
| INIT → MONITORING | M1 发送 M7_ACTIVATE 信号（ODD 进入正常运行） | 初始化 publisher；启动 10Hz 定时器 |
| MONITORING → DEGRADED | `AssumptionStatus.total_violation_count >= 1 && <= 2` | 发布 Safety_AlertMsg（severity=WARNING）；SOTIF 告警升级 |
| MONITORING → VIOLATED | `AssumptionStatus.total_violation_count >= 3` | 发布 Safety_AlertMsg（severity=CRITICAL）；触发 MRC 请求 → M1 |
| DEGRADED → MONITORING | 所有违反假设清除（`total_violation_count == 0`）持续 ≥ 5 周期（50ms 消抖） | 清除告警标志；恢复 10Hz 正常发布 |
| VIOLATED → MONITORING | MRC 执行完毕 + `reset()` 调用 + ODD 状态恢复 | 所有滑窗清零；计数器复位 |

> **注**：`Safety_AlertMsg` 的发布由 M7-core 处理（D3.3a 范围）。M7-sotif 将 `AssumptionStatus` 写入共享状态，由 M7-core 的 `SafetyAlertGenerator` 消费。
