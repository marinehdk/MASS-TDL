## 1. 概述

M5 TacticalPlanner 实现**双层 MPC** 避碰轨迹生成，将 M4 BehaviorPlan（行为意图）与 M6 COLREGsConstraint（规则约束）转化为可执行轨迹：

- **Mid-MPC**：CasADi 3.6.3 + IPOPT 二阶优化，90s 时域（N=18 步 × 5s），1–2 Hz。输出 `AvoidancePlan`（4-WP + speed_adjustments）→ L4 Guidance Layer。
- **BC-MPC**：Eriksen 2020 分支树算法，10–30s 时域，≤10 Hz 事件驱动。输出 `ReactiveOverrideCmd`（ψ_cmd, u_cmd, ROT_cmd）→ L4 紧急覆盖。

**Backseat Driver 模式**：所有船型参数从 `CapabilityManifest` YAML 运行时加载，决策核心零硬编码常量。

**X-axis Deterministic Checker VETO**：M5 输出须经 X-axis Checker 否决检查后方可到达 L4（§11.7 架构报告）。

### 2.2 状态机（Mid-MPC ↔ BC-MPC 切换）

```
    ┌──────────┐    Mid-MPC 收敛       ┌──────────────┐
    │          │◄───────────────────────│              │
    │ NORMAL   │                        │  AVOIDANCE   │
    │ (Mid-MPC │──────────────────────▶│  (Mid-MPC    │
    │  主导)    │   CPA < CPA_safe      │   主导)       │
    │          │   或 M6 规则触发        │              │
    └────┬─────┘                        └──────┬───────┘
         │                                     │
         │ 连续 3 次 Mid-MPC 失败               │ 短时 CPA < CPA_safe × 0.8
         │ 或 IPOPT 超时 > 30ms × 3             │
         ▼                                     ▼
    ┌──────────────┐                   ┌──────────────┐
    │              │    CPA 恢复安全     │              │
    │  FALLBACK    │◄──────────────────│  REACTIVE    │
    │  (Nomoto     │                   │  (BC-MPC     │
    │   RRT*)      │                   │   主导)       │
    │              │                   │              │
    └──────────────┘                   └──────────────┘
```

- **NORMAL → AVOIDANCE**：Mid-MPC 检测到 CPA < CPA_safe(ODD) 或 M6 触发 COLREGs 规则
- **AVOIDANCE → REACTIVE**：BC-MPC 检测到短时域 CPA < CPA_safe × 0.8 且 Mid-MPC 连续失败 ≥ 3
- **REACTIVE → AVOIDANCE**：BC-MPC 评估 CPA 恢复 → BcMpcSolution::Status::Resolved
- **Mid-MPC → FALLBACK**：连续 3 次 IPOPT solve > 30ms → 触发 RRT* fallback
- **FALLBACK → NORMAL**：连续 10 次 RRT* solve < 25ms → 尝试恢复 Mid-MPC

## 3. Mid-MPC 详细设计

### 3.1 优化问题形式化

```
min     J  =  w_colreg · J_colreg  +  w_dist · J_dist  +  w_vel · J_vel
x∈R²ᴺ

where   x = [ψ₀, ψ₁, ..., ψ_{N-1};  u₀, u₁, ..., u_{N-1}]   (N=18)
        p ∈ R⁹³   (parameter vector, see §3.4)

s.t.    |ψ_{k+1} - ψ_k|  ≤  ROT_max(u_k, Hs) · dt          ∀k∈[0,N-2]   (1)
        u_min ≤ u_k ≤ u_max                                   ∀k∈[0,N-1]   (2)
        ψ_min ≤ ψ_k ≤ ψ_max                                   ∀k∈[0,N-1]   (3)
        CPA(ψ_k, target_i) ≥ CPA_safe(ODD)                   ∀k, ∀i       (4)
        ENC_check(x_k, y_k) = SAFE                            ∀k           (5)
        COLREGs directional (Rule 14/15/16/17)               ∀k           (6)
```

**目标函数分解**：

| 项 | 含义 | 权重 [TBD-HAZID] | 公式 |
|---|---|---|---|
| J_colreg | COLREGs 规则合规代价（软约束） | w_colreg = 1000.0 | ∑_k Σ_i max(0, CPA_safe - CPA(ψ_k, target_i))² |
| J_dist | 路径偏离代价 | w_dist = 10.0 | ∑_k dist(waypoint_k, planned_route)² |
| J_vel | 速度效率代价 | w_vel = 1.0 | ∑_k (u_k - u_planned)² |

**硬约束（g(x, p) ≥ 0，IPOPT 公约）**：

| 约束 | 维度 | 说明 |
|---|---|---|
| ROT 限制 | N-1 = 17 | `rot_max*dt - |dpsi_k| >= 0` |
| 速度边界 | N = 18 | `u_k - u_min >= 0`, `u_max - u_k >= 0` |
| 航向边界 | N = 18 | `psi_k - psi_min >= 0`, `psi_max - psi_k >= 0` |
| CPA 安全 | N × max_targets (≤ 288) | per-target per-step CPA ≥ CPA_safe |
| ENC 区域 | variable | point-in-polygon 半平面测试 |
| COLREGs 方向 | variable | 按生效规则编译 |

总约束维度：g_dim = 5N - 1 = 89（不含 CPA/ENC/COLREGs 变量约束）。

### 3.2 CasADi/IPOPT 求解配置

```yaml
solver: ipopt
  max_iter: 150             # [TBD-HAZID]
  tol: 1.0e-4              # [TBD-HAZID]
  max_cpu_time: 0.45s      # 450ms 硬超时（SLA 500ms cap）
  acceptable_tol: 1.0e-3   # 可接受次优解
  linear_solver: mumps     # open-source；ma27/ma57 HSL 可选
  hessian_approximation: limited-memory  # L-BFGS
  print_level: 0           # 生产环境关闭 stdout
  warm_start_init_point: yes
  warm_start_bound_push: 1.0e-4
  warm_start_mult_bound_push: 1.0e-4
```

**求解超时处理**：

```
if solve_duration_ms > 30:    # 第 1 次超阈值
    log warning, 继续使用解
if consecutive_timeouts >= 3: # 连续 3 次 > 30ms
    trigger RRT* fallback
    重置 consecutive_timeouts = 0
    if RRT* fallback duration > 1.0s:
        trigger MRM-01 (减速至安全速度)
```

| 超时阈值 | 动作 | 理由 |
|---|---|---|
| solve_duration_ms ≤ 25ms | 正常（目标） | SIL 1 实时性要求 |
| 25ms < t ≤ 30ms | 接受，记录 | 单次尖峰 |
| 30ms < t ≤ 450ms | 接受解，计数器 +1 | IPOPT max_cpu_time 内 |
| t > 450ms | IPOPT 自终止 | CasADi callback 触发 |
| 连续 3 次 > 30ms | → RRT* fallback | 防止级联延迟 |
| RRT* > 1.0s | → MRM-01 减速 | 安全兜底 |

### 3.3 Warm-Start 策略

```
function warm_start_validate(prev_solution, current_input) -> bool:
    // 状态有效性校验
    dt_since_prev = current_input.stamp_ns - prev_solution.stamp_ns
    if dt_since_prev > 2.0s:
        return false  // 间隔过长，状态已过期
    
    // 速度变化校验
    delta_u = |current_input.own_ship.u_mps - prev_solution.trajectory[0].u_mps|
    if delta_u > 3.0 m/s:
        return false  // 速度大幅变化，线性外推不可靠
    
    // 航向变化校验
    delta_psi = angular_delta(current_input.own_ship.psi_rad,
                               prev_solution.trajectory[0].psi_rad)
    if delta_psi > 15°:
        return false  // 航向变化过大
    
    // 目标集变化校验
    if target_ids_changed(current_input.targets, prev_solution):
        return false  // 目标集变化，warm start 无效
    
    return true  // 复用上一帧解

if warm_start_valid:
    x0 = pack_shifted_trajectory(prev_solution)  // 时间前移 1 步
    lambda0 = prev_solution.dual_variables
else:
    x0 = cold_start(current_input)  // 常航向 + 常速度外推
    lambda0 = zeros
```

**冷启动**：`x0 = [ψ₀, ψ₀, ..., ψ₀; u₀, u₀, ..., u₀]`（N 次重复当前状态），保证可行性。

## 4. BC-MPC 详细设计

### 4.1 分支树算法（Eriksen 2020 [R20]）

```
算法：BC-MPC argmax-min CPA 选择

输入：own_ship_state, targets[], cpa_safe_m, urgency_level

1. 确定候选数 k：
   if urgency_level > 0.95:    k = 13, range = ±60°  (P2-B-01)
   elif urgency_level > 0.8:   k = 7,  range = ±30°
   else:                        k = 5,  range = ±20°

2. 生成候选航向：
   for i in [0, k):
       ψ_candidate[i] = ψ_current + δψ × (i - ⌊k/2⌋)
       where δψ = 10°

3. 预测本船轨迹（N=10 步 × 2s = 20s 时域）：
   for each ψ_candidate[i]:
       traj[i] = predict_own_positions(x0, y0, ψ_candidate[i], u_current)
       // 使用 4-DOF MMG 恒定航向前向积分

4. 预测目标轨迹（所有 intent 假设）：
   for each target[j]:
       for intent in {Maintain, TurnPort, TurnStarboard, Decelerate}:
           tgt_traj[j][intent] = predict_target_positions(target[j], intent)

5. 评估最坏情况 CPA：
   for each ψ_candidate[i]:
       worst_cpa[i] = +∞
       for each target[j]:
           for each intent:
               cpa = CpaCalculator::compute_trajectory(traj[i], tgt_traj[j][intent])
               worst_cpa[i] = min(worst_cpa[i], cpa.cpa_m)

6. 选择最优候选：
   i* = argmax_i worst_cpa[i]
   if worst_cpa[i*] < cpa_safe_m * override_cpa_multiplier:
       return ReactiveOverrideCmd(ψ_candidate[i*])
   else:
       return BcMpcSolution::Status::Resolved
```

### 4.2 参数配置

| 参数 | 默认值 [TBD-HAZID] | 说明 |
|---|---|---|
| k_high | 7 | urgency > 0.8 时候选数 |
| k_low | 5 | urgency ≤ 0.8 时候选数 |
| k_critical | 13 | urgency > 0.95 时候选数（P2-B-01, ±60°） |
| δψ | 10° | 候选间隔 |
| dt_s | 2.0s | 预测步长 |
| horizon_s | 20.0s | 预测时域 |
| urgency_threshold | 0.8 | 分级阈值 |
| override_cpa_multiplier | 0.8 | 触发 OVERRIDE 的 CPA 系数 |
| validity_s | 1.0s | 紧急命令有效期 |

### 4.3 BC-MPC 触发条件

BC-MPC 在每个 Mid-MPC 周期后评估，满足以下任一条件即激活完整分支树求解：

| 条件 | 触发逻辑 | 代码标识 |
|---|---|---|
| CONDITION_A | predicted_short_horizon_cpa_m < cpa_safe_m × 0.8 | CPA 急剧恶化 |
| CONDITION_B | mid_mpc_consecutive_failures ≥ 3 | Mid-MPC 连续失败 |
| CONDITION_C | 任一 target.tcpa_s < 30s 且置信度 > 0.7 | 近距离紧迫 |
| CONDITION_D | M1 ODDState.alert_level ≥ WARNING | ODD 告警升级 |

**不触发条件**：M1 `override_active = true`（人工接管时 BC-MPC 冻结，不输出 ReactiveOverrideCmd）。

### 5.2 Nomoto 线性化 Fallback 实现范围

当 `M5_USE_CASADI=OFF` 或 IPOPT 连续超时时，使用**一阶 Nomoto 模型**：

```
Nomoto 1st-order:
    T · ṙ + r = K · δ

where:
    T = 时延常数 [s]（从 CapabilityManifest 估算）
    K = 增益常数 [1/s]
    r = 转首率 [rad/s]
    δ = 舵角 [rad]

离散形式 (Forward Euler):
    r_{k+1} = r_k + (dt/T) · (K·δ - r_k)
    ψ_{k+1} = ψ_k + r_k · dt
    x_{k+1} = x_k + u · cos(ψ_k) · dt
    y_{k+1} = y_k + u · sin(ψ_k) · dt
```

**DEMO-2 fallback 范围**：
- 约束检查：仅 CPA + ROT_max 硬约束（无 COLREGs 方向约束、无 ENC 区域约束）
- N = 12 步 × 5s = 60s（短时域）
- 输出仅 trajectory_candidates[]；不发布 AvoidancePlan（L4 仍用 L2 PlannedRoute）
- 13 条候选航向的几何分支：`ψ_current + i·δψ, i ∈ [-6, 6], δψ=10°`

**CPP 实现路径**：在 `mid_mpc_solver.cpp` 中 `#ifndef M5_HAS_CASADI` 条件编译块内，新增 `solve_nomoto_fallback()` 静态函数。

| `|Δψ_k| ≤ ROT_max(u, Hs)·dt` | CapabilityManifest → VesselDynamicsModel | 硬约束 | SIL 1 |
| `CPA ≥ CPA_safe(ODD)` | M1 ODD_StateMsg | 硬约束 | SIL 2（DC ≥ 90%） |
| `u_min ≤ u_k ≤ u_max` | M4 BehaviorPlan + M1 ODD | 硬约束 | SIL 1 |
| `ψ_min ≤ ψ_k ≤ ψ_max` | M4 BehaviorPlan | 硬约束 | SIL 1 |
| ENC 区域约束 | M2 WorldState + ENC 查询 | 硬约束 | SIL 1 |
| COLREGs 方向约束 | M6 COLREGsConstraint | 硬约束 | SIL 2（MISRA-C++ CC < 15） |

### 6.2 X-axis Deterministic Checker VETO

```
MidMpcNode::publish_avoidance_plan():
    plan = waypoint_generator.generate(solution)
    if plan.status == "NORMAL":
        pub_avoidance_plan_->publish(plan)
        // X-axis Checker 独立订阅此 topic
        // 如 VETO → CheckerVetoNotification → M7 → M1 → M5 冻结
```

M5 自身不做 VETO 检查——这是 X-axis Checker（系统层独立轴）与 M7 Safety Supervisor 的职责。

### 6.3 人工接管时行为

当 M1 发布 `override_active = true` 时：
- Mid-MPC：停止求解，最后输出 `AvoidancePlan.status = "OVERRIDDEN"`
- BC-MPC：停止求解，不发布 `ReactiveOverrideCmd`
- 所有 ASDR 记录标记 `"overridden"`
- 回切时积分项重置，从当前状态重新冷启动

## 8. 内存安全（8h 连续运行）

### 8.1 禁止动态分配路径

所有 MPC 求解路径遵循**零堆分配**原则：

| 对象 | 分配策略 | 生命周期 |
|---|---|---|
| CasADi MX/DM | CasADi 内部管理（LGPL 边界，SIL 豁免） | per-solve 自动回收 |
| IPOPT 工作向量 | IPOPT 内部分配（LGPL 边界，SIL 豁免） | solve() 返回后释放 |
| Eigen 矩阵/向量 | 栈分配（固定大小） | 函数作用域 |
| std::vector（内部类型） | 预分配 + `reserve()` + 复用 | 节点生命周期 |
| ROS2 消息 | 智能指针 `SharedPtr` | ROS2 中间件管理 |

### 8.2 内存泄漏检测

- CI 集成 Valgrind memcheck（Debug 构建，30min 持续运行测试）
- ASan 构建（Debug）：`-fsanitize=address`（CasADi 链接目标除外）
- 8h 持续集成测试：D3.7 全系统集成中监控 RSS 变化 < 5%

### 8.3 禁止路径

- `malloc` / `free`：禁止（MISRA C++:2023 Rule 18-4-1）
- `new` / `delete`：禁止（用 `std::make_unique` 或栈分配替代）
- 动态 `std::vector` 在 solve 热路径中 resize：禁止（用固定大小 `std::array` 或预分配 + `reserve`）

## 10. 设计决策记录

### DD-001：DEMO-2 Nomoto Fallback 简化范围

**决策**：DEMO-2 仅提供 13 条几何分支（运动学），无 COLREGs intent-min 评估。CPA 用线性 CPA 公式（CpaCalculator::compute_linear），不运行完整分支树。

**理由**：7/27 前 Nomoto stub 仅需最小可行输出供前端渲染。完整 Eriksen 2020 argmax-min 在 DEMO-3 升级。

**影响**：DEMO-2 的 trajectory_candidates[] 中 `cpa_m` 值为线性 CPA（不含 intent 不确定性），`rule_compliant` 均为 false。

### DD-002：trajectory_candidates IDL 设计

**决策**：独立消息 `TrajectoryCandidate`（非嵌入 `AvoidancePlan`），通过 `SAT3Data.trajectory_candidates[]` 发布。

**理由**：
- SAT-3 数据通道独立于 L4 控制通道，前端 `MpcTrajectoryLayer` 消费 SAT-3 即可
- 13 条候选（含 BC-MPC 全部分支 + Mid-MPC 主轨迹）语义统一
- `is_primary` 标记区分 Mid-MPC 主解和各 BC-MPC 候选

**替代方案**：嵌入 `AvoidancePlan` 附加字段 → 拒绝原因：混合控制通道与可视化通道违反关注点分离。

### DD-003：Warm-Start 有效性校验

**决策**：5 条件校验（时间间隔、速度变化、航向变化、目标集变化、求解状态），任一条失败 → 冷启动。

**理由**：
- 复用过期解比冷启动更危险（IPOPT 从不可行初始点恢复困难）
- 校验开销 O(1)，远小于 IPOPT 内部迭代
- 冷启动（常值外推）保证初始可行性

### DD-004：IPOPT 超时 → RRT* Fallback 阈值

**决策**：单次 > 30ms 记录 warning；连续 3 次 > 30ms → RRT* fallback；RRT* > 1.0s → MRM-01。

**理由**：
- 25ms 目标基于 1Hz 的 2.5% CPU 预算（1 核 @ 3GHz）
- 30ms 阈值留有 5ms 抖动容忍
- 3 次连续超时避免单次尖峰导致不必要降级
- RRT* 1.0s 超时触发 MRM-01（减速至安全速度）作为最终安全网

### DD-005：8h 内存安全策略

**决策**：热路径（solve()）全部栈分配 + 预分配复用；CasADi/IPOPT 内部分配由 LGPL 库边界隔离。

**理由**：
- MISRA C++:2023 禁止动态分配（Rule 18-4-1）
- CasADi/IPOPT 作为外部 LGPL 库，内部 MISRA 违规按 coding-standards.md §10 豁免
- 8h 运行验证：CI 持续集成测试 + Valgrind memcheck

**替代方案**：自定义内存池 → 拒绝原因：过度设计（LGPL 库边界已隔离），增加认证复杂度。
